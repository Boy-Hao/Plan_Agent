# 12 数据模型与存储

## 1. 存储选型

| 数据 | 存储 | 理由 |
|---|---|---|
| 业务实体（用户/Agent/Skill/配置） | MySQL 8 | 事务、关系、成熟运维 |
| 会话消息/用量/审计 | MySQL 8（按月分区/归档） | 结构化查询、对账 |
| SSE/会话状态/配额/锁/缓存 | Redis 7 | 低延迟、原子操作、Pub/Sub |
| 文件/Skill 包/大文本 | OSS（S3 兼容） | 成本、版本、签名 URL |
| 搜索（可选） | OpenSearch/ES | 全文检索、日志 |
| 指标/日志/Trace | Prometheus/Loki/Tempo | 可观测 |

---

## 2. 建模约定

- 主键：`*_id` 字符串（ULID/UUID），不暴露自增。
- 公共字段：`create_time`、`update_time`、`create_user_id`、`update_user_id`、`is_deleted`、`delete_time`。
- 软删除：`is_deleted=0/1`；查询默认过滤。
- 逻辑唯一：项目规范禁用 DB UNIQUE KEY，应用层查重 + 幂等键 + 读端容忍。
- 金额：`DECIMAL(18,6)`；token：`BIGINT`；比例：`DECIMAL(8,4)`。
- 时间：UTC 存储，接口 ISO 8601。
- JSON：MySQL `JSON` 类型存扩展配置；高频查询字段拆列。
- 多租户：所有表加 `tenant_id`（即使首版单租户）。

## 4. 索引与性能

| 场景 | 索引 |
|---|---|
| 会话列表 | `(user_id, is_deleted, last_active_time DESC)` |
| 消息 | `(session_id, create_time, message_id)` |
| 用量 | `(create_time, user_id)`、`(agent_id, create_time)`、`(llm_config_id, create_time)` |
| Agent 搜索 | `(owner_id, is_deleted)`、`(visibility, is_deleted)`、name 前缀 |
| Skill 搜索 | `(category_id, is_deleted)`、`(owner_id, is_deleted)`、name |
| 审计 | `(resource_type, resource_id, create_time)`、`(user_id, create_time)` |
| 通知 | `(user_id, read_status, create_time DESC)` |

**原则**
- 避免 `%keyword%` 全表扫；必要上搜索。
- 分页用「游标 + 覆盖索引」优于大 offset。
- 大表按月分区（用量/审计/消息归档）。
- 读多写少配置加 Redis 缓存 + 本地 LRU。

## 5. Redis 键设计

| 前缀 | 用途 | TTL |
|---|---|---|
| `t:{tenant}:sso:access:{jti}` | 会话存活 | access TTL |
| `t:{tenant}:sso:refresh:{jti}` | 刷新 | refresh TTL |
| `t:{tenant}:perm:user:{id}` | 权限缓存 | 5–10 min |
| `t:{tenant}:session:active_turn:{sid}` | 活跃轮 | 1 h |
| `t:{tenant}:sse:log:{mid}` | SSE ring buffer | 1 h |
| `t:{tenant}:sse:live:{mid}` | Pub/Sub | 无 |
| `t:{tenant}:lock:session:{sid}` | 会话锁 | 30 s |
| `t:{tenant}:quota:{pool}:bucket` | 令牌桶 | 持续 |
| `t:{tenant}:quota:{pool}:waiters` | 排队 | 持续 |
| `t:{tenant}:idem:{key}` | 幂等 | 24 h |
| `t:{tenant}:nonce:{app_id}:{nonce}` | 签名防重放 | 10 min |
| `t:{tenant}:oauth:state:{state}` | OAuth state | 10 min |
| `t:{tenant}:bridge:space:{code}` | 嵌入空间 | 1 h |
| `t:{tenant}:notify:unread:{uid}` | 未读数 | 无 |
| `t:{tenant}:ratelimit:{scope}:{id}` | 限流 | 窗口 |

**规范**：所有 key 带租户前缀；禁止大 key（>1MB）；Stream 限制长度；Pub/Sub 不保证持久化，需配合 log。

## 6. OSS 布局

```
/{tenant}/
  files/{user_id}/{file_id}/{filename}
  avatars/{agent_id}/{hash}.png
  personas/{agent_id}/{hash}.zip
  skills/{skill_id}/{version}/...
  personal-skills/{user_id}/{skill_id}/{version}/...
  attachments/{session_id}/{file_id}/{filename}
  artifacts/{session_id}/{artifact_id}/...
  data-pages/{page_key}/{version}/...
  exports/{export_id}/...
```

- 对象 key 不可猜测；访问必须签名。
- 版本控制开启；生命周期规则（回收站 30 天、临时文件 7 天）。
- 跨区域复制（可选）；加密（SSE-KMS/SSE-OSS）。
- 大文件分片上传；断点续传。

## 7. 数据生命周期

| 数据 | 保留 | 清理 |
|---|---|---|
| 会话/消息 | 1–3 年（可配） | 软删 → 归档 → 物理删 |
| 附件 | 随会话；回收站 30 天 | 生命周期 |
| 用量 | 2 年 | 聚合后删明细 |
| 审计 | ≥ 1 年（合规） | 归档 |
| 调用链 | 30–90 天 | 采样/清理 |
| SSE ring buffer | 1 小时 | TTL |
| 沙箱工作目录 | 任务结束 | 立即清理 |
| 导出文件 | 7 天 | 定时清理 |

**删除权**：用户可删除自己的会话/文件；管理员可执行合规删除；删除需审计。

## 8. 迁移与兼容

- Alembic 版本化；禁止手改生产表。
- 采用「扩展 → 双写 → 迁移 → 收缩」四步，保证可回滚。
- 大表变更用 online DDL/gh-ost（MySQL）。
- 迁移前备份；迁移后校验行数/关键指标。
- 回滚脚本与演练。

## 9. 多租户

| 层 | 设计 |
|---|---|
| DB | 所有表 `tenant_id`；联合索引前缀 |
| Redis | key 前缀 `t:{tenant}:` |
| OSS | 路径前缀 `/{tenant}/` |
| 日志 | 结构化字段 `tenant_id` |
| 网关 | 域名/Header 解析租户 |
| 计费 | 按租户聚合 |

**隔离级别**：共享库共享表（首版）→ 大租户独立库/独立桶（规模化）。

---

## 10. 备份与容灾

| 项 | 目标 |
|---|---|
| MySQL | 每日全备 + binlog；RPO ≤ 15 min；异地 |
| Redis | AOF + 定期 RDB；可从 DB 重建关键状态 |
| OSS | 版本 + 跨区复制（可选） |
| 恢复演练 | 每季度一次 |
| 数据校验 | 每日关键表行数/金额对账 |

## 11. 验收标准

- [ ] 核心表有 ER 图与字段说明。
- [ ] 所有查询有索引支撑，慢查询 < 1%。
- [ ] 软删、审计、租户字段全覆盖。
- [ ] Redis key 有命名规范与 TTL。
- [ ] OSS 路径不可枚举，签名 URL 可用。
- [ ] 迁移可回滚，备份可恢复。
