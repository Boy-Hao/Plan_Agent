# 00 主次总纲与依赖编排

## 1. 一句话

**先把「能安全地跑通一轮对话」做到生产级，再谈多 Agent、飞书、治理、优化。**

---

## 2. 优先级分层

### T0：生死线（不做就不成立）

| 模块 | 为什么是 T0 | 失败后果 |
|---|---|---|
| 身份/权限/租户 | 谁能进、能看什么 | 越权/泄露 |
| 运行时/SSE | 一轮对话的正确性 | 丢消息/重复/卡死 |
| 模型网关/配额 | 模型可用、成本可控 | 429/账单爆炸 |
| Skill/MCP 工具链 | 工具怎么被选/调 | 选错/注入/不可用 |

### T1：支撑线（不做不能生产）

| 模块 | 为什么是 T1 | 失败后果 |
|---|---|---|
| 沙箱/执行 | 代码任务隔离 | 逃逸/滥用 |
| 文件/OSS | 附件/产物 | 丢失/泄露 |
| 数据/分区 | 规模与一致性 | 慢/丢 |
| 管理端 | 配置/运营 | 无法管理 |
| 可观测/运维 | 定位/止损 | MTTR 高 |

### T2：增强线（不做不能规模化）

| 模块 | 为什么是 T2 | 失败后果 |
|---|---|---|
| 飞书/GitLab/A2A | 进入工作流 | 采用率低 |
| 多 Agent | 复杂任务 | 成本/复杂 |
| 权限审计 | 合规 | 审计不通过 |
| OSS 治理 | 成本/合规 | 成本失控 |
| 调度/数据页 | 自动化 | 效率低 |

### T3：优化线（不做不可持续）

| 模块 | 为什么是 T3 | 失败后果 |
|---|---|---|
| 性能/延迟 | 体验 | 用户流失 |
| 成本/单位经济 | 可持续 | 预算超 |
| 评测/实验 | 防退化 | 越改越差 |
| 缓存/路由 | 降本增效 | 贵/慢 |

## 3. 依赖图

```
身份/权限/租户
   │
   ├──> Agent 配置 ──> 模型网关/配额
   │        │                │
   │        └──────┬─────────┘
   │               ▼
   │          运行时/SSE
   │               │
   │        ┌──────┼──────────┐
   │        ▼      ▼          ▼
   │    Skill/MCP  文件/OSS   沙箱/执行
   │        │      │          │
   │        └──────┼──────────┘
   │               ▼
   │          管理端/可观测
   │               │
   │        ┌──────┼──────────┐
   │        ▼      ▼          ▼
   │     飞书/GitLab 多Agent  治理/审计
   │        │      │          │
   │        └──────┼──────────┘
   │               ▼
   │          优化/评测/成本
```

**关键路径**：身份 → Agent/模型 → 运行时 → Skill/MCP → 沙箱/文件 → 管理/可观测 → 集成/治理 → 优化。

## 6. 决策规则

### 6.1 什么时候可以进下一层

| 进入 | 条件 |
|---|---|
| T0 → T1 | 黄金路径 7 天稳定；越权 0；SSE 续传 ≥99.9% |
| T1 → T2 | 备份/恢复演练通过；P95 达标；告警/值班就绪 |
| T2 → T3 | 有评测集；成本可归因；有灰度能力 |

### 6.2 什么时候必须回退

- T0 错误率 > 1% → 冻结新功能。
- 越权/泄露 → 立即停服排查。
- 成本超预算 50% → 配额/降级。
- 质量下降 > 2% → 回滚优化。
