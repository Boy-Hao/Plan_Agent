# 03 第一主线：模型网关与配额

> 定位：**T0 生死线**。它决定「模型可用、成本可控、故障可降级」。
> 失败后果：429 频繁、账单爆炸、单供应商故障全站不可用。

---

## 1. 成败标准

| 标准 | 目标 |
|---|---|
| 模型可用性 | ≥99.5% |
| 429 拒绝率 | <5%（正常） |
| 配额超发 | ≤0.1% |
| 首 token P95 | ≤3s |
| 单任务成本 | ≤预算 |
| 故障切换 | ≤30s |
| 密钥泄露 | 0 |

---

## 2. 网关职责

```
业务/Runtime
  ↓
Model Gateway
  ├─ Provider 适配
  ├─ 能力注册
  ├─ 参数合并
  ├─ 配额准入
  ├─ 重试/降级/熔断
  ├─ 用量/计费
  └─ 审计/日志
  ↓
Provider
```

**原则**：业务只依赖 `llm_config_id`，不直接依赖厂商 SDK。

---

## 3. 路由策略（主次）

### 3.1 基础路由

```
显式模型 → 能力过滤 → 配额准入 → 调用
未指定 → Agent 默认 → 备用 → 全局默认
```

### 3.2 能力过滤

- 工具调用、视觉、思考、JSON、上下文长度。
- 不满足 → 明确报错，不静默降级。

### 3.3 成本/延迟路由（P1）

```
简单任务 → 小模型
中等 → 中模型
复杂 → 大模型
高价值/高风险 → 大模型 + 校验
```

### 3.4 级联（P2）

小模型先答 → 校验/置信度 → 不足升级大模型。
护栏：质量下降即回退。

---

## 4. 配额池

### 4.1 参数

| 参数 | 说明 |
|---|---|
| configured_tpm | 持续容量 |
| burst_seconds | 突发 = tpm/60 × burst |
| cache_ratio | 缓存折算 |
| max_admission_wait_ms | 最大等待 |
| max_waiter_count | 最大排队 |
| max_waiting_tokens | 最大预占 |
| mode | OBSERVE/ENFORCE |

### 4.2 算法

```
effective = prompt × (1 - cache_hit × (1 - cache_ratio))
refill = elapsed × tpm/60
bucket = min(capacity, bucket + refill)
if bucket >= effective: admit
elif OBSERVE: admit + record
elif queue allowed: enqueue
else: 429 quota_exceeded
```

- Redis Lua 原子；服务端时间。
- 大池分片；快照/对账。
- OBSERVE 记录 would_wait/would_reject。

### 4.3 模式

| 模式 | 用途 |
|---|---|
| OBSERVE | 校准 |
| ENFORCE | 成本控制 |
| 共享池 | 多模型 |
| 独占池 | 关键业务 |
| 不限流 | 测试 |

## 5. 参数合并

```
registry 默认 ← llm_config 覆盖 ← agent_binding 覆盖 ← session 覆盖
```

返回 `effective_values` + `value_sources`，可解释。
超出范围拒绝；能力变更预览影响。

---

## 6. 降级与熔断

| 场景 | 策略 |
|---|---|
| 429 | 排队 → 备用 → 报错 |
| 5xx | 重试 1 次 → 备用 |
| 超时 | 缩短输出/切模型 |
| 上下文超限 | 裁剪 → 长上下文 |
| 能力不支持 | 明确报错 |
| 供应商故障 | 熔断 30s + 备用 |
| 内容拦截 | 安全提示 |

**熔断**：错误率 >30%/1min → 打开 → 半开探测。

---

## 7. 计费与对账

```
cost = (prompt-cached)×price_in + cached×price_cache + completion×price_out
```

- 按调用时价格快照。
- 每次调用落明细（user/agent/model/session）。
- 日对账；差异 > 阈值告警。
- 成本按租户/Agent/模型归因。

---

## 8. 安全

- 密钥加密（KMS/Vault）；只在网关解密。
- 日志不记录 prompt/密钥。
- 出站白名单；禁 SSRF。
- 沙箱只拿短期代理 token。
- 轮换/禁用/删除审计。

---

## 9. 失败模式

| 失败 | 行为 |
|---|---|
| 密钥无效 | 401 + 配置提示 |
| 模型不存在 | 404 |
| 配额拒绝 | 429 + reset |
| 供应商 5xx | 熔断/备用 |
| 计费异常 | 告警/对账 |
| 能力变更 | 影响预览/清理 |
| 删除模型 | 解绑/影响分析 |

---

## 10. 实施顺序

1. Provider 适配（2 个）。
2. LLM 配置 CRUD/加密/掩码。
3. 连通性测试。
4. 能力注册表/参数合并。
5. 配额池 OBSERVE。
6. 用量/计费。
7. 降级/熔断。
8. ENFORCE/对账。
9. 级联/路由（P2）。
