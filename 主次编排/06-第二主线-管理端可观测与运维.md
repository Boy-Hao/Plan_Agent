# 06 第二主线：管理端、可观测与运维

> 定位：**T1 支撑线**。没有它，系统「能跑但管不了、看不到、救不回」。
> 失败后果：配置错误无法回滚、故障定位慢、容量/成本失控。

---

## 1. 成败标准

| 标准 | 目标 |
|---|---|
| 核心接口可用性 | ≥99.9% |
| 首 token P95 | ≤3s |
| 故障定位 | ≤5min |
| P0 MTTR | ≤30min |
| 告警有效率 | ≥80% |
| 配置回滚 | ≤5min |
| 备份恢复 | 季度演练通过 |

---

## 2. 管理端

### 2.1 必备页面（T1）

- 用户/角色/权限。
- Agent 管理。
- 模型配置/测试/绑定。
- 配额池（OBSERVE）。
- 沙箱配置/实例。
- 文件/用量/反馈。
- 系统参数/变量。
- 审计日志。

### 2.2 交互原则

- 列表：筛选/分页/批量/空态/错误。
- 表单：校验/默认值/继承来源/未保存提示。
- 危险操作：影响预览 + 二次确认。
- 密钥：一次性展示 + 掩码。
- 配置：版本/回滚/审计。

---

## 3. 可观测

### 3.1 指标

| 层 | 指标 |
|---|---|
| 平台 | QPS/错误/延迟 |
| AI | TTFT/模型错误/429/token/成本 |
| SSE | 连接/断连/续传 |
| 沙箱 | 创建/失败/回收 |
| DB/Redis | 连接/慢查/内存 |
| 集成 | 飞书/GitLab 成功率 |

### 3.2 日志

- 结构化 JSON；request_id/trace_id。
- 不记录密钥/prompt/附件正文。
- 审计单独存储。

### 3.3 Trace

- 请求 → 会话 → LLM/工具/子 Agent。
- 采样：成功 10%、失败 100%、慢 100%。
- 前端可查调用链。

---

## 4. SLO/告警

| 服务 | SLO |
|---|---|
| 登录 | 99.9% |
| 对话 | 99.5% |
| API | 99.9% |
| 通知 | 99.5% |

**告警分级**
- P0：登录全挂/5xx>10%/DB 不可用 → 5min。
- P1：TTFT P95>8s/错误>5% → 15min。
- P2：配额拒绝>10%/沙箱失败>5% → 1h。
- P3：单 Agent/成本波动 → 次日。

---

## 5. 运维

### 5.1 日常

- 健康/错误/延迟。
- DB/Redis/队列。
- 模型/沙箱/集成。
- 备份/告警。

### 5.2 发布

```
CI → 镜像 → dev → test → uat → prod 金丝雀 → 全量
```

- 迁移先备份/可回滚。
- 观察 30min。
- 自动回滚阈值。

### 5.3 Runbook

- 登录失败。
- 对话 5xx。
- 模型 429。
- Redis 故障。
- MySQL 切换。
- 沙箱异常。
- 飞书断连。
- OSS 容量。

---

## 6. 容量/成本

- API/Runtime/SSE/沙箱/DB/Redis 阈值。
- 自动扩缩；大促前压测。
- 成本按租户/Agent/模型归因。
- 预算告警。

---

## 7. 失败模式

| 失败 | 行为 |
|---|---|
| 配置错误 | 版本回滚 |
| 告警风暴 | 聚合/抑制 |
| 监控缺失 | 补指标/黑盒 |
| 发布故障 | 回滚/灰度 |
| 备份失败 | 告警/重试 |
| 容量不足 | 扩容/限流 |

---

## 8. 实施顺序

1. 管理端骨架/权限。
2. 用户/角色/Agent/模型页面。
3. 指标/日志/Trace。
4. 告警/值班。
5. 发布/回滚。
6. 备份/恢复。
7. 容量/成本看板。

---
