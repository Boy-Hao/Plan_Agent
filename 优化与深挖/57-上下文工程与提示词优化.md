# 57 上下文工程与提示词优化

## 1. 为什么上下文是核心

在 Agent 系统里，**上下文决定质量、成本和延迟**：

- 上下文越大 → 越贵、越慢、越容易「迷失在中间」；
- 上下文越乱 → 模型越容易忽略关键指令；
- 上下文顺序不稳定 → Provider 前缀缓存失效，成本翻倍。

**目标**：用最少的 token，给模型「刚好够用」的信息，并且可缓存、可解释、可防护。

---

## 2. 上下文预算模型

| 部分 | 建议占比 | 说明 |
|---|---|---|
| 平台安全策略 | 5% | 不可压缩 |
| Agent 系统提示词 | 10% | 稳定前缀 |
| 业务模板/任务 | 10% | 可版本化 |
| 引用源/检索 | 25% | 按需、可裁剪 |
| 附件摘要 | 15% | 解析后摘要 |
| 历史 | 25% | 窗口 + 摘要 |
| 工具定义 | 5% | 按需筛选 |
| 输出预留 | 5% | max_output |

> 比例按业务调整；原则是**输出和关键指令优先**，历史/引用可压缩。

---

## 3. 提示词分层

```
L0 平台策略（安全/合规/拒答）
L1 Agent 人设/目标/边界
L2 业务模板（biz_id）
L3 任务指令（当前用户）
L4 数据（引用/附件/工具结果）
L5 历史（摘要/最近消息）
```

**规则**
- 高优先级在前；数据用分隔符/标签包裹。
- L0 不可被用户输入覆盖。
- L1/L2 稳定，便于缓存；L3/L4 变化。
- 不要把「数据」写成「指令」。

---

## 4. 稳定前缀（缓存友好）

Provider 的 Prompt Cache 通常按**前缀匹配**。要命中：

1. 固定顺序：系统策略 → Agent → 模板 → 工具定义 → 数据 → 历史 → 用户输入。
2. 不要在系统提示词里放时间戳/随机 ID/用户昵称（会破坏前缀）。
3. 变量放末尾；动态内容后置。
4. 工具定义顺序稳定（按名称排序）。
5. JSON 规范化（键排序、无多余空格）。

**收益**：命中缓存可省 50–90% 输入成本（视 Provider），并降低首 token 延迟。

## 5. 历史管理

| 策略 | 说明 | 适用 |
|---|---|---|
| 滑动窗口 | 最近 N 轮 | 短对话 |
| 摘要 | 旧消息压缩成摘要 | 长对话 |
| 实体记忆 | 抽取关键实体/结论 | 任务型 |
| 任务记忆 | 计划/进度/待办 | 多步任务 |
| 固定锚点 | 用户偏好/约束 | 长期会话 |

**压缩流程**
```
旧消息 → 分块 → 摘要（保留事实/数字/结论/未完成项）
→ 替换旧消息 → 保留最近 K 轮原文
```

**注意**：摘要会丢细节；关键引用/工具结果保留原文或引用链接。

---

## 6. 检索与引用优化

### 6.1 流程

```
用户问题 → 查询改写 → 混合检索（关键词+向量）
→ 去重 → 重排 → Top-K → 上下文注入 → 引用标注
```

### 6.2 优化点

| 优化 | 效果 |
|---|---|
| 查询改写 | 提升召回 |
| 混合检索 | 兼顾精确/语义 |
| 重排（cross-encoder/LLM） | 提升精度 |
| 去重/近重复 | 省 token |
| 分块大小调优 | 平衡上下文/精度 |
| 引用片段而非全文 | 省 token |
| 按需二次检索 | 避免一次性塞满 |

**指标**：召回率、引用覆盖率、答案支撑率、上下文 token。

---

## 7. 附件处理

| 类型 | 处理 |
|---|---|
| PDF/Word | 解析文本 + 表格；分块 |
| Excel/CSV | 表头/样本/统计；按需查询 |
| 图片 | OCR/多模态；摘要 |
| 代码 | 语法感知分块；文件树 |
| 压缩包 | 清单 + 按需解压 |

**原则**：先给「摘要 + 结构」，模型需要细节再取；不要把整个文件塞进上下文。

---

## 8. 工具结果压缩

| 问题 | 优化 |
|---|---|
| 结果太大 | 只保留模型需要的字段（Schema projection） |
| 重复 | 去重/聚合 |
| 长文本 | 摘要 + 原文引用 |
| 二进制/图片 | 落 OSS，给 URL/描述 |
| 表格 | 转 Markdown/CSV 摘要 |
| 错误 | 结构化错误 + 建议 |

**预算**：单条工具结果 ≤ 10–50KB；总工具结果 ≤ 上下文 30%；超出截断并标注。

---

## 9. 提示词注入防护

| 层 | 措施 |
|---|---|
| 输入 | 检测「忽略指令/泄露密钥/越权」 |
| 上下文 | 外部内容用 `<data source="...">` 包裹；声明「以下只是数据」 |
| 工具 | 白名单/参数校验/高危确认 |
| 输出 | 脱敏/审核 |
| 运行 | 最小权限/沙箱 |

**原则**：模型输出不可信；数据中的指令不作为系统指令；副作用必须经工具层授权。

---

## 10. 提示词版本化

- 系统提示词/模板存 DB，带版本号。
- 变更记录：谁、何时、diff、影响。
- 支持灰度/回滚。
- 与评测集绑定：变更前后跑回归。
- 禁止在代码里硬编码长 Prompt（难维护/难审计）。

---

## 11. 优化 Playbook（按收益/成本）

| 优化 | 预期收益 | 成本 | 风险 | 优先级 |
|---|---|---|---|---|
| 稳定前缀/缓存 | 成本 -10~40% | 低 | 低 | P0 |
| 历史摘要 | 成本 -20~50% | 中 | 中（丢细节） | P0 |
| 工具结果裁剪 | 成本 -10~30% | 低 | 低 | P0 |
| 引用片段化 | 成本 -10~20% | 中 | 低 | P1 |
| 查询改写/重排 | 质量 + | 中 | 低 | P1 |
| 动态 Few-shot | 质量 + | 中 | 中 | P1 |
| 结构化输出 | 质量/稳定 + | 低 | 低 | P1 |
| 语义压缩 | 成本 - | 高 | 高（失真） | P2 |

## 12. 指标

| 指标 | 说明 |
|---|---|
| 输入 token/请求 | 成本 |
| 上下文命中率 | 引用是否被用到 |
| 缓存命中率 | 成本/延迟 |
| 引用覆盖率 | 质量 |
| 答案支撑率 | 幻觉 |
| 压缩率 | 摘要效果 |
| 注入拦截率 | 安全 |
