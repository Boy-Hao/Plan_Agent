# 58 工具选择与模型路由优化

## 1. 两个核心问题

1. **工具太多**：几十个 Skill/MCP 工具全塞给模型 → 选错、贵、慢。
2. **模型太多**：全用大模型 → 贵；全用小模型 → 质量差。

优化目标：**用对的工具、对的模型，完成任务**，而不是「最多工具 + 最大模型」。

---

## 2. 工具选择链路

```
用户输入
→ 意图识别（规则/小模型）
→ 工具召回（关键词/向量/标签）
→ 工具重排（规则/LLM/学习模型）
→ Top-K（如 5–15）
→ 生成工具定义
→ 模型选择/调用
```

### 2.1 工具元数据

| 字段 | 用途 |
|---|---|
| name/alias | 唯一、稳定 |
| description | 何时用/不用 |
| tags | 领域/动作 |
| risk | read/write/danger |
| input_schema | 参数 |
| examples | 触发示例 |
| owner/version | 治理 |

### 2.2 召回策略

| 策略 | 优点 | 缺点 |
|---|---|---|
| 关键词 | 快、可控 | 覆盖低 |
| 向量检索 | 语义泛化 | 需 embedding |
| 标签过滤 | 精准 | 依赖标注 |
| 规则 | 确定性强 | 维护成本 |
| 混合 | 兼顾 | 复杂 |

**建议**：标签 + 关键词 + 向量混合；先过滤权限/可用性，再召回。

### 2.3 重排

- 规则：意图→工具白名单。
- LLM：给候选工具+描述，让模型选 Top-K（成本低，效果好）。
- 学习模型：用历史调用训练（需数据）。
- 阈值：低于阈值不暴露，直接回答/追问。

### 2.4 工具数量

| 工具数 | 建议 |
|---|---|
| ≤10 | 全量 |
| 10–30 | 分组/按意图筛选 |
| >30 | Tool RAG + Top-K |

**注意**：工具描述也会占 token；Top-K 要平衡召回与上下文。

---

## 3. 工具描述优化

| 问题 | 优化 |
|---|---|
| 描述太长 | 只写「何时用/不用」+ 关键限制 |
| 参数不清 | JSON Schema 完整、枚举、示例 |
| 名称冲突 | `alias__tool` 前缀 |
| 工具重叠 | 合并/拆分；明确边界 |
| 缺少示例 | 1 个正例/1 个反例 |
| 结果格式 | 声明返回结构，便于模型使用 |

**反模式**：把整篇文档塞进 description；模型记不住，还贵。

---

## 4. 确定性快路径

不是所有请求都要模型选工具：

| 场景 | 快路径 |
|---|---|
| 明确命令（`/skill xxx`） | 直接调用 |
| 结构化查询（订单号/车型） | 正则/规则解析 |
| 固定报表 | 模板 + 参数 |
| 高频问题 | 缓存/FAQ |
| 附件类型明确 | 直接走解析工具 |

**收益**：省一次 LLM 调用、降低误选、提升稳定性。

## 5. 模型路由

### 5.1 路由维度

| 维度 | 说明 |
|---|---|
| 能力 | 工具/视觉/思考/JSON/上下文 |
| 难度 | 简单/中等/复杂 |
| 成本 | 单价 × token |
| 延迟 | TTFT/总时长 |
| 配额 | 池余额/排队 |
| 可用性 | 熔断/错误率 |
| 合规 | 数据分级/地域 |

### 5.2 难度分类

| 信号 | 简单 | 复杂 |
|---|---|---|
| 输入长度 | 短 | 长 |
| 工具需求 | 无/1 个 | 多步/多工具 |
| 任务类型 | 改写/翻译/抽取 | 推理/规划/代码 |
| 历史 | 短 | 长 |
| 用户要求 | 简单问答 | 深度分析 |
| 失败重试 | 首次 | 已失败 |

**实现**：规则 + 小模型分类器；输出 `difficulty ∈ {easy, medium, hard}` + 置信度。

### 5.3 路由策略

```
if 显式模型: 用显式
elif 有视觉/长上下文/工具: 过滤能力
elif difficulty=easy: 小模型
elif difficulty=medium: 中模型
else: 大模型
→ 配额准入 → 失败降级
```

### 5.4 级联（Cascade）

```
小模型先答 → 置信度/校验
  ├─ 通过 → 返回（省成本）
  └─ 不通过 → 升级大模型（带小模型草稿/错误）
```

**适用**：问答、抽取、分类、简单工具调用。
**风险**：升级判断错误；需要质量护栏。
**收益**：30–60% 成本下降（视任务分布）。

### 5.5 投机/并行（可选）

- 小模型先流式输出，同时大模型后台生成；质量不够时切换（体验复杂）。
- 多模型并行投票（成本高，适合高价值）。

### 5.6 学习型路由（P2）

- 用历史（任务、模型、质量、成本）训练 bandit/分类器。
- 冷启动用规则；逐步探索。
- 需要反馈信号（点赞/完成/人工）。

## 6. 成本/延迟计算示例

假设：
- 小模型：输入 ¥1/M，输出 ¥4/M，TTFT 0.8s
- 大模型：输入 ¥10/M，输出 ¥40/M，TTFT 1.8s
- 每次输入 6k、输出 800

```
小模型成本 = 6×1 + 0.8×4 = ¥9.2/千次
大模型成本 = 6×10 + 0.8×40 = ¥92/千次
```

若 70% 任务小模型可完成：
```
混合成本 = 0.7×9.2 + 0.3×92 = ¥34.0/千次
相比全大模型节省 ≈ 63%
```
延迟：70% 请求 TTFT 0.8s，P95 可能仍在 2s 内。

## 7. 失败与降级

| 场景 | 策略 |
|---|---|
| 工具选错 | 观察错误 → 重选（最多 1–2 次） |
| 工具不可用 | 过滤/跳过/替代 |
| 小模型质量差 | 升级大模型 |
| 大模型 429 | 排队/小模型/备用 |
| 路由置信度低 | 用默认模型/追问 |
| 循环调用 | 检测相同工具+参数，停止 |
| 预算耗尽 | 返回部分结果 |

| 指标 | 说明 |
|---|---|
| 工具 Precision/Recall | 选对/漏选 |
| 平均工具数 | 效率 |
| 平均轮次 | 效率 |
| 升级率 | 级联效果 |
| 单任务成本 | 成本 |
| 首 token/完整延迟 | 体验 |
| 任务完成率 | 质量 |
| 路由准确率 | 分类器 |

## 9. 优化 Playbook

| 优化 | 收益 | 成本 | 风险 | 优先级 |
|---|---|---|---|---|
| 工具分组/Top-K | 准确率+/成本- | 中 | 低 | P1 |
| 工具描述优化 | 准确率+ | 低 | 低 | P0 |
| 确定性快路径 | 成本-/稳定+ | 低 | 低 | P0 |
| 难度分类+级联 | 成本 -30~60% | 中 | 中 | P1 |
| 学习型路由 | 成本- | 高 | 高 | P2 |
| 工具结果裁剪 | 成本- | 低 | 低 | P0 |

---

## 10. 验收标准

- [ ] 工具按权限/能力/可用性过滤。
- [ ] 工具数 >30 时有召回/重排/Top-K。
- [ ] 工具描述简洁、Schema 完整、命名不冲突。
- [ ] 有确定性快路径。
- [ ] 模型路由可按难度/成本/能力。
- [ ] 级联有质量护栏与升级策略。
- [ ] 路由/工具选择可解释、可观测。
- [ ] 成本/延迟/质量同时达标。
