# 61 成本优化与单位经济

## 1. 成本结构

```
总成本 = LLM + 沙箱 + 基础设施 + 存储/流量 + 运维/人力 + 第三方
```

| 项 | 典型占比（早期） | 驱动 |
|---|---|---|
| LLM | 30–60% | 输入 token、输出、轮次、模型单价 |
| 沙箱 | 10–30% | 并发、时长、节点 |
| 基础设施 | 15–25% | API/Runtime/DB/Redis |
| 存储/流量 | 5–15% | 文件、日志、CDN |
| 运维/人力 | 固定 | 团队 |

---

## 2. 单位经济指标

| 指标 | 公式 | 用途 |
|---|---|---|
| 单会话成本 | 会话总成本 / 会话数 | 业务对比 |
| 单任务成本 | 任务总成本 / 完成任务数 | 价值 |
| 单用户成本 | 月总成本 / 月活 | 预算 |
| 单 Agent 成本 | Agent 总成本 / 调用 | 归因 |
| 单 token 成本 | 总成本 / 总 token | 效率 |
| 成功率成本 | 总成本 / 成功任务 | 真实成本 |

**关键**：不要只看「每千 token 单价」，要看「完成一个任务花多少钱」。

---

## 3. 成本公式

### 3.1 LLM

```
cost = (prompt - cached) × price_in/1e6
     + cached × price_cache/1e6
     + completion × price_out/1e6
```

### 3.2 沙箱

```
cost = 并发 × 时长 × 单价
     + 预热池空闲 × 单价
```

### 3.3 基础设施

```
cost = 节点数 × 单价 + DB/Redis/OSS + 流量
```

### 3.4 单任务

```
task_cost = Σ llm_calls + Σ tools + sandbox_time + overhead
```

## 4. 成本驱动分析

| 驱动 | 影响 | 优化 |
|---|---|---|
| 输入 token | 最大 | 上下文压缩/缓存 |
| 输出 token | 大 | 限制/格式 |
| 轮次/工具 | 大 | 工具选择/提示 |
| 模型单价 | 大 | 分级/级联 |
| 重试 | 中 | 幂等/熔断 |
| 缓存命中 | 中 | Prompt/语义缓存 |
| 沙箱时长 | 中 | lazy/暂停/共享 |
| 存储/日志 | 小 | 生命周期/采样 |

## 7. 预算与归因

| 维度 | 用途 |
|---|---|
| 租户 | 收费/配额 |
| 部门 | 成本分摊 |
| Agent | 场景 ROI |
| 用户 | 异常/滥用 |
| 模型 | 供应商谈判 |
| 时间 | 趋势/预算 |

**机制**
- 每日成本报表；预算阈值告警（50/80/100%）。
- 超预算：限流/降级/审批。
- 成本标签：tenant/agent/model/session。
- 对账：平台计量 vs 供应商账单。

## 8. 成本护栏

| 护栏 | 说明 |
|---|---|
| 配额池 | TPM/等待/拒绝 |
| 单用户限额 | 日/月 token |
| 单 Agent 限额 | 防止一个场景打爆 |
| max_output | 防止超长 |
| 轮次/工具上限 | 防止循环 |
| 缓存 | 减少重复 |
| 降级 | 高峰用便宜模型 |

---

## 9. 示例测算

假设 1,000 DAU、10 轮/人、6k 输入/800 输出、大模型 ¥10/¥40 每百万：

```
日输入 = 60M → ¥600
日输出 = 8M → ¥320
日成本 ≈ ¥920；月 ≈ ¥27,600
```

优化后：
- 缓存 30% 输入 → 省 ¥180/日
- 摘要/裁剪 20% 输入 → 省 ¥120/日
- 级联 50% 任务小模型 → 省约 ¥250/日
- 合计月省 ≈ ¥16,500（约 60%）

## 10. 反模式

| 反模式 | 后果 |
|---|---|
| 只看单价不看任务成本 | 选便宜模型但轮次多，更贵 |
| 无配额 | 单场景打爆 |
| 全量大模型 | 成本高 |
| 缓存不失效 | 脏数据/重复事故 |
| 过度压缩 | 质量下降，重试更贵 |
| 日志全量长保留 | 存储成本 |
