# 62 多 Agent 与任务规划优化

## 1. 先问：真的需要多 Agent 吗

多 Agent 带来：上下文隔离、并行、专业化；也带来：成本、延迟、协调复杂度、失败面。

| 场景 | 单 Agent 够吗 | 建议 |
|---|---|---|
| 1–5 步工具 | 够 | 单 Agent ReAct |
| 长文档/多文件 | 可能 | 单 Agent + 并行工具 |
| 跨领域/多角色 | 不够 | 多 Agent |
| 可并行子任务 | 可能 | 单 Agent + 并行工具，或子 Agent |
| 需要独立上下文/预算 | 不够 | 子 Agent |
| 高风险多步 | 不够 | 多 Agent + 人工确认 |

**原则**：能用单 Agent + 工具/并行解决，不要多 Agent。

---

## 2. 拓扑

| 拓扑 | 结构 | 适用 | 风险 |
|---|---|---|---|
| Supervisor | 主 Agent 派发/汇总 | 常见 | 主 Agent 瓶颈 |
| Hierarchical | 多层主管 | 大型任务 | 成本/延迟 |
| Pipeline | 串行阶段 | 固定流程 | 不灵活 |
| Swarm | 对等协作 | 探索型 | 难收敛 |
| Debate | 多观点评审 | 高价值决策 | 成本高 |

**推荐**：Supervisor 起步；固定流程用 Pipeline；Debate 仅高价值。

## 3. 规划器设计

### 3.1 输出

```json
{
  "goal": "...",
  "tasks": [
    {"id":"t1","title":"...","agent":"bom","deps":[],"budget":{"tokens":8000,"seconds":120},"acceptance":"..."},
    {"id":"t2","title":"...","agent":"quality","deps":["t1"],"budget":{...}}
  ],
  "parallel_groups": [["t1","t3"],["t2"]]
}
```

### 3.2 规则

- 任务可度量（有验收标准）。
- 依赖是 DAG；无环。
- 每任务有预算。
- 可并行的显式分组。
- 失败策略：重试/跳过/升级。
- 计划版本化；可重规划。

### 3.3 反模式

- 计划太细（每步都调模型）→ 贵。
- 计划太粗（一个大任务）→ 不可控。
- 无预算 → 无限。
- 无验收 → 无法判断完成。

## 4. 执行优化

| 优化 | 说明 | 收益 |
|---|---|---|
| 并行 fan-out | 无依赖任务并行 | 延迟 - |
| 结果摘要 | 子 Agent 只回摘要/引用 | 上下文 - |
| 预算分配 | 按任务复杂度 | 成本 - |
| 早停 | 达到目标即停 | 成本 - |
| 计划模板 | 常见任务复用 | 延迟/成本 - |
| 跳过规划 | 简单任务直接 ReAct | 成本 - |
| 结果缓存 | 相同子任务复用 | 成本 - |
| 并发限制 | 防打爆模型/沙箱 | 稳定 |

---

## 5. 上下文隔离

```
父 Agent
  ├─ 子 Agent A（独立 session/上下文）
  ├─ 子 Agent B（独立 session/上下文）
  └─ 汇总：摘要 + 产物引用 + 关键结果
```

- 子 Agent 不直接写父会话。
- 父只收结构化结果，避免上下文爆炸。
- 子 Agent 有独立预算/超时/取消。
- 结果带来源/置信度。

---

## 6. 失败与恢复

| 失败 | 策略 |
|---|---|
| 子任务超时 | 重试/跳过/升级 |
| 子 Agent 循环 | 检测/停止 |
| 依赖失败 | 重规划/降级 |
| 结果冲突 | 父 Agent 裁决/人工 |
| 总预算耗尽 | 返回部分结果 |
| 死锁 | DAG 校验/超时 |

---

## 7. 成本模型

```
多 Agent 成本 ≈ 规划成本 + Σ 子 Agent 成本 + 汇总成本
```

- 规划本身是一次 LLM 调用（可能多次）。
- 子 Agent 上下文独立，重复系统提示词 → 成本。
- 汇总可能再调一次大模型。
- 并行不减少 token，只减少墙钟时间。

**结论**：多 Agent 通常更贵；只在「单 Agent 做不好/太慢」时用。

## 8. 优化 Playbook

| 优化 | 收益 | 成本 | 风险 | 优先级 |
|---|---|---|---|---|
| 简单任务跳过规划 | 成本 - | 低 | 低 | P0 |
| 结果摘要/引用 | 上下文 - | 低 | 低 | P0 |
| 并行 fan-out | 延迟 - | 中 | 中 | P1 |
| 计划模板 | 成本/延迟 - | 中 | 中 | P1 |
| 预算分配 | 成本 - | 中 | 低 | P1 |
| 子任务缓存 | 成本 - | 高 | 中 | P2 |
| 学习型规划 | 质量 + | 高 | 高 | P3 |

## 9. 指标

| 指标 | 说明 |
|---|---|
| 任务完成率 | 质量 |
| 多 Agent 使用率 | 是否过度 |
| 子任务成功率 | 执行 |
| 并行度 | 效率 |
| 规划成本占比 | 成本 |
| 总延迟/成本 | 对比单 Agent |

## 10. 验收标准

- [ ] 有「是否需要多 Agent」的决策矩阵。
- [ ] 计划是 DAG、有预算/验收。
- [ ] 子 Agent 上下文隔离、结果摘要。
- [ ] 失败可重试/跳过/重规划。
- [ ] 多 Agent 成本可对比单 Agent。
- [ ] 简单任务不强制多 Agent。
- [ ] 有并行/早停/模板优化。
