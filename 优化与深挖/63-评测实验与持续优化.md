# 63 评测、实验与持续优化

## 1. 目标

- 证明优化「真的有效」，而不是感觉有效。
- 防止「优化一个、退化两个」。
- 让 Prompt/模型/Skill/路由的变更可回归、可灰度、可回滚。

---

## 2. 评测金字塔

```
        ┌──────────────┐
        │ 人工评审/用户反馈 │  少、贵、准
        ├──────────────┤
        │ 在线 A/B/灰度    │  真实、慢
        ├──────────────┤
        │ LLM-as-Judge    │  快、有偏
        ├──────────────┤
        │ 规则/单元评测    │  快、确定
        └──────────────┘
```

**原则**：规则先行，LLM Judge 扩展，人工校准，线上验证。

---

## 3. 评测集（Golden Set）

| 类型 | 内容 | 规模 |
|---|---|---|
| 任务成功 | 真实任务 + 期望结果 | 100–300 |
| 工具选择 | 期望工具/参数 | 50–100 |
| 引用 | 期望引用/来源 | 50 |
| 安全 | 注入/越权/敏感 | 50–100 |
| 边界 | 空/超长/多语言 | 30 |
| 回归 | 历史 badcase | 持续积累 |

**要求**
- 覆盖主要 Agent/场景/模型。
- 有标准答案或评分 rubric。
- 版本化；变更需评审。
- 不包含敏感数据（脱敏）。

---

## 4. 指标

| 维度 | 指标 |
|---|---|
| 质量 | 任务完成率、正确率、引用覆盖率、幻觉率 |
| 工具 | 选择准确率、参数正确率、平均轮次 |
| 体验 | 首 token、完整延迟、失败率 |
| 成本 | token、费用、缓存命中 |
| 安全 | 注入拦截、越权、敏感泄露 |
| 用户 | 点赞率、重试率、放弃率 |

**北极星**：单位成本下的任务完成率。

---

## 5. LLM-as-Judge

### 5.1 Rubric 示例

| 分数 | 标准 |
|---|---|
| 5 | 完全正确、有引用、格式符合 |
| 4 | 基本正确、少量遗漏 |
| 3 | 部分正确、需人工补充 |
| 2 | 明显错误/幻觉 |
| 1 | 无关/有害 |

### 5.2 注意

- Judge 有偏（位置/长度/模型偏好）；需校准。
- 用固定模型/温度；盲评；交换顺序。
- 与人工样本对比，计算一致性。
- 不用于高风险最终决策（人工复核）。

---

## 6. 实验设计

| 方法 | 适用 | 注意 |
|---|---|---|
| 离线回归 | 每次变更 | 快、无用户影响 |
| 影子流量 | 新模型/新链路 | 不影响用户 |
| 金丝雀 | 小流量 | 观察指标 |
| A/B | 策略对比 | 样本量/显著性 |
| 灰度 | 按用户/租户 | 可回滚 |

**原则**：先离线，再影子，再小流量，再全量。

---

## 7. 统计与显著性

- 明确指标与最小可检测效应（MDE）。
- 样本量 = f(基线率、MDE、α、β)。
- 避免 peeking/多重比较。
- 看置信区间，不只看均值。
- 业务指标与质量指标同时看。

**示例**：点赞率从 80%→82%，需要足够样本；不要 100 次就下结论。

---

## 8. 版本与回归

| 资产 | 版本 | 回归 |
|---|---|---|
| Prompt | 版本号/diff | 评测集 |
| Skill | 版本/回滚 | 调用测试 |
| 模型配置 | 版本/能力 | 能力/成本 |
| 路由策略 | 配置版本 | A/B |
| 工具描述 | 版本 | 工具准确率 |

**门禁**：质量下降 > 阈值 → 阻断发布；成本上升 > 阈值 → 复核。

---

## 9. Badcase 闭环

```
线上失败/差评 → 归因（上下文/工具/模型/数据）
→ 修复（Prompt/Skill/工具/路由）
→ 加入评测集 → 回归 → 灰度 → 观察
```

**归因分类**：意图误判、工具选错、参数错、上下文缺失、模型能力、数据错误、安全问题、体验问题。

---

## 10. 看板

- 质量：完成率/正确率/引用/幻觉。
- 工具：准确率/轮次。
- 延迟：TTFT/完整/P95。
- 成本：单任务/单会话/模型分布。
- 安全：拦截/越权/泄露。
- 实验：分组/置信区间。

---

## 11. 优化循环

```
Observe（指标/ badcase）
→ Hypothesize（假设）
→ Experiment（离线/影子/AB）
→ Measure（质量/成本/延迟）
→ Decide（上线/回滚）
→ Monitor（持续）
```

**频率**：每周小实验；每月大版本；每季度架构级优化。

---

## 12. 验收标准

- [ ] 有 Golden Set 与评分标准。
- [ ] 每次 Prompt/模型/Skill 变更跑回归。
- [ ] LLM Judge 与人工一致性可接受。
- [ ] 有影子/金丝雀/A/B 能力。
- [ ] 优化有质量/成本/延迟三指标。
- [ ] Badcase 闭环到评测集。
- [ ] 发布有质量/成本门禁。
