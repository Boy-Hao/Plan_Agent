# 64 优化方案库与 ROI 排序

> 30+ 可落地优化项。每项标注：问题、方案、收益、投入、风险、指标、优先级。
> 评分：收益/投入/风险均 1–5；优先级综合判断（P0 先做，P3 观望）。

---

## 1. 使用方式

1. 先做 P0（低风险、快收益）。
2. 用 63 的评测验证，再灰度。
3. 每季度复盘 ROI，淘汰低效优化。
4. 不要一次上 10 个；**一次 1–2 个，可归因**。

## 4. 30/60/90 天路线

### 0–30 天（Quick Wins）

- O-01 稳定前缀 + O-18 Prompt 缓存
- O-02 历史摘要 + O-03 工具结果裁剪
- O-23 SSE 合并/防缓冲 + O-24 DB 批量
- O-33 max_output + O-34 轮次/工具上限
- O-30 沙箱 lazy/暂停 + O-35 存储生命周期
- O-40 熔断/降级 + O-42 调用链

**预期**：成本 -20~40%，首 token -10~20%，稳定性提升。

### 31–60 天（结构性）

- O-10 工具 Top-K + O-11 描述优化
- O-13 难度分类 + O-14 模型级联
- O-26 并行工具/检索 + O-27 独立 SSE 网关
- O-19/20 检索/Embedding 缓存
- O-31 预热池 + O-25 分区
- O-41 幂等/重试预算

**预期**：成本再 -20~30%，总延迟 -20%，吞吐 +。

### 61–90 天（实验/规模化）

- O-04 引用片段化 + O-05/06 改写/重排
- O-21 语义缓存（小范围，严格护栏）
- O-38 并行 fan-out + O-39 计划模板
- O-44 容量模型 + O-47 沙箱隔离加固
- O-16 学习型路由（数据足够再上）

**预期**：质量 +，成本再 -10%，规模化就绪。

## 5. 反优化（不要做）

| 反优化 | 为什么 |
|---|---|
| 过早微服务 | 复杂度 > 收益 |
| 全量语义缓存 | 一致性/隐私风险 |
| 盲目多 Agent | 成本/延迟上升 |
| 过度压缩上下文 | 质量下降，重试更贵 |
| 只看单价选模型 | 任务成本更高 |
| 无评测的 Prompt 调优 | 无法证明有效 |
| 全量日志长保留 | 存储成本 |
| 所有工具全暴露 | 选择困难/贵 |

---

## 6. 决策规则

1. 先做 **低风险 + 可回滚** 的。
2. 每次只改 1–2 个变量，便于归因。
3. 质量下降 > 2% 即回滚（除非业务接受）。
4. 成本优化必须看「单任务成本」，不是「单 token」。
5. 高风险优化（语义缓存/学习路由）必须小流量 + 人工抽检。
6. 任何优化都要进评测集/看板。
