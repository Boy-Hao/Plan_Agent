# 优化与深挖篇

> 目标：在「能跑」之后，回答**怎么更快、更便宜、更稳、更准**。
> 本目录不重复功能设计，只做三件事：**深挖机制、量化瓶颈、给出可落地的优化方案与 ROI。**

---

## 1. 优化总原则

1. **先测量，后优化**：没有基线（P50/P95、token、成本）不动手。
2. **先做零风险**：缓存、批处理、索引、提示词稳定排序。
3. **再做结构性优化**：模型级联、工具检索、上下文压缩、多 Agent 降本。
4. **最后做实验性优化**：语义缓存、学习型路由、自动 Prompt 优化。
5. **每次优化都要有护栏**：质量、成本、延迟、安全四类指标同时看。

## 3. 优化优先级（先做这些）

| 优先级 | 优化 | 预期收益 | 风险 |
|---|---|---|---|
| P0 | Prompt 稳定前缀 + Provider 缓存 | 成本 -10~40% | 低 |
| P0 | 历史摘要 + 工具结果裁剪 | 成本 -20~50% | 低 |
| P0 | DB 批量写 + 索引 + 分区 | 延迟/稳定性 | 低 |
| P0 | SSE 事件合并 + 背压 | 吞吐 + | 低 |
| P1 | 工具检索/分组（Tool RAG） | 准确率 + 成本 - | 中 |
| P1 | 模型级联（小模型优先） | 成本 -30~60% | 中 |
| P1 | 检索重排 + 去重 | 准确率 + 成本 - | 中 |
| P1 | 沙箱 lazy/暂停/预热池 | 成本 - | 中 |
| P2 | 语义缓存 | 成本/延迟 - | 高（一致性/隐私） |
| P2 | 学习型路由 | 成本 - | 高（需数据） |
| P2 | 多 Agent 计划模板复用 | 成本/延迟 - | 中 |

## 4. 优化看板（必须同时看）

| 维度 | 指标 |
|---|---|
| 质量 | 任务完成率、工具准确率、引用覆盖率、点赞率 |
| 延迟 | 首 token P50/P95、完整响应 P95、工具 P95 |
| 成本 | 单会话/单任务成本、token/请求、缓存命中率 |
| 稳定 | 错误率、超时率、降级率、循环率 |
| 安全 | 注入拦截率、越权 0、敏感数据泄露 0 |

**规则**：任何优化不能让质量下降超过阈值；成本下降但质量下降不算成功。

## 5. 使用方式

- 架构/性能评审：先看 64 的 ROI 表，选 3 个 Quick Win。
- 线上变慢/变贵：按 60/61 的瓶颈树定位。
- 回答不准：按 57/58 的上下文/工具链路排查。
- 要上多 Agent：先看 62 的决策矩阵，避免过度设计。
- 每次优化：按 63 做实验与回归，防止「优化一个、退化两个」。
