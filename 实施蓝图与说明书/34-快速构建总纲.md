# 34 快速构建总纲

## 1. 构建目标

用 **8–10 人、12 周**，从空仓库搭出一个可用的平台：

- 用户能 SSO 登录；
- 管理员能创建 Agent、配置模型；
- 用户能和 Agent 流式对话、上传附件、使用 1–2 个 Skill；
- 有历史、权限、基础用量；
- 能部署到测试环境，10–50 人试用。

**不是**一次做完 495 个接口；而是做一条**黄金路径**，再按模块扩展。

---

## 2. 黄金路径（Golden Path）

```
登录 → Agent 广场 → 选择 Agent → 创建会话 → 发送消息
→ SSE 流式回复 → 调用 1 个 Skill → 上传 1 个附件
→ 刷新恢复历史 → 点赞 → 管理员看到用量
```

**任何模块的首版都必须服务这条路径**；不服务它的功能延后。

---

## 3. 构建顺序与依赖

```
[0] 基础设施（DB/Redis/OSS/CI）
      │
[1] 身份权限（SSO/JWT/RBAC/ACL）
      │
[2] Agent（CRUD/绑定） ── [3] 模型网关（Provider/配置）
      │                         │
      └──────────┬──────────────┘
                 ▼
[4] 会话运行时（Session/Message/SSE/Tool）
      │
[5] Skill（上传/解析/绑定/调用）
      │
[6] 文件（上传/签名/附件）
      │
[7] 沙箱（配置/任务/Git）
      │
[8] 配额（TPM/计费）
      │
[9] 集成（飞书/GitLab/A2A）
      │
[10] 治理（审计/权限审计/OSS）
      │
[11] 规模化（压测/灰度/多租户）
```

**关键路径**：0 → 1 → 2/3 → 4 → 5 → 6 → 8 → 9 → 10。
沙箱（7）可以与 5/6 并行，但不要阻塞 MVP。

## 5. 模块实现模板（Golden Module）

新增一个模块，按这个顺序做，避免返工：

### Step 1：领域

- 写聚合/实体/值对象/枚举。
- 写不变量与状态机。
- 写单元测试（不依赖 DB）。

### Step 2：数据

- 迁移：表、索引、约束（逻辑）。
- Repository：只做 CRUD/查询。
- 集成测试（testcontainers）。

### Step 3：应用

- Service：用例编排、事务边界、权限调用。
- 事件：需要跨上下文时写 outbox。

### Step 4：接口

- Pydantic 请求/响应。
- 路由：鉴权、权限、参数、错误。
- OpenAPI 描述。

### Step 5：前端

- API client + Query key。
- 页面/表单/列表/空态/错误。
- 权限显隐。

### Step 6：生产化

- 指标/日志/Trace。
- 超时/重试/降级。
- 配置项/默认值。
- Runbook/验收。

## 7. 首版技术决策（默认值）

| 项 | 默认 | 备注 |
|---|---|---|
| 架构 | 模块化单体 + Runtime 独立 | 不拆微服务 |
| DB | MySQL 8 | utf8mb4，软删 |
| 缓存 | Redis 7 | 单主从起步 |
| 队列 | Redis Streams/ARQ | 不上 Kafka |
| 对象存储 | S3 兼容（MinIO/OSS） | 预签名 |
| Agent | LangGraph/DeepAgents | 先单 Agent |
| 流式 | SSE | 不上 WebSocket |
| 沙箱 | E2B 托管/兼容 | 先 lazy |
| 部署 | Docker Compose → K8s | 先单环境 |
| 鉴权 | OIDC SSO + JWT | 先单租户 |
| 特性开关 | JSON/环境变量 | 不上 Unleash |

## 8. 环境与种子

| 环境 | 用途 | 种子 |
|---|---|---|
| local | 开发 | 2 用户、2 Agent、1 Skill、1 模型（mock） |
| dev | 联调 | 测试租户 |
| test | 自动化 | 脱敏 |
| uat | 验收 | 仿真 |
| prod | 生产 | 真实 |

**种子脚本**必须包含：
- 超管/普通用户；
- 1 个公开 Agent + 1 个私有 Agent；
- 1 个模型配置（mock 或测试 Key）；
- 1 个 Skill 包；
- 1 个配额池（OBSERVE）。

## 9. 质量门禁

| 门禁 | 标准 |
|---|---|
| Lint/类型 | 0 error |
| 单测 | 后端 ≥70%，核心 ≥80% |
| 契约 | OpenAPI 通过 |
| 迁移 | 可执行/可回滚 |
| 安全 | 无高危；密钥 0 硬编码 |
| 性能 | 首 token P95 ≤3s（测试环境） |
| E2E | 黄金路径通过 |
| 文档 | 模块说明 + Runbook |

## 10. 快速构建的 10 个加速器

1. **模板仓库**：直接复制目录/配置/CI。
2. **Mock 优先**：外部集成先 Mock，前端不等后端。
3. **契约优先**：OpenAPI 生成类型。
4. **种子数据**：一键起 demo。
5. **特性开关**：未完成功能隐藏，不阻塞发布。
6. **托管服务**：DB/Redis/OSS/沙箱先用托管。
7. **单体优先**：不拆服务，减少联调。
8. **一条黄金路径**：不做全量功能。
9. **自动化回归**：E2E 覆盖核心。
10. **每周可演示**：避免「最后一周集成」。

## 11. 常见返工点

| 返工点 | 预防 |
|---|---|
| SSE 后补续传 | 第一天设计 ring buffer |
| 权限只做前端 | 第一天后端强校验 |
| 模型 Key 泄露 | 第一天加密/脱敏 |
| 表没租户字段 | 第一天加 `tenant_id` |
| 消息表没分区 | 第一天按月分区 |
| 事件无版本 | 第一天定 schema |
| 外部集成无 Mock | 第一天适配器 |
| 配额后补 | 模型上线前 OBSERVE |
| 审计后补 | 高危操作先记录 |
| 成本后知后觉 | 第一天打标签 |
