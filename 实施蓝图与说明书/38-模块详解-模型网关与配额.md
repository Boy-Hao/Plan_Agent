# 38 模块详解：模型网关与配额

## 1. 职责与边界

**负责**
- Provider 接入（OpenAI 兼容/Anthropic/Azure/DeepSeek/Qwen/自建）。
- 模型配置（地址/密钥/模型/价格/能力）。
- 能力注册表与参数合并。
- 配额池（TPM/突发/等待/模式）。
- 用量计量、计费、降级、熔断。

**不负责**：Agent 提示词（Agent）、会话状态（Conversation）、沙箱（Execution）。

## 3. Provider 适配

```python
class LLMProvider(Protocol):
    async def chat(self, req: ChatRequest) -> AsyncIterator[Chunk]: ...
    async def list_models(self) -> list[ModelInfo]: ...
    async def ping(self) -> PingResult: ...
    async def capabilities(self, model: str) -> ModelCapabilities: ...
```

**统一错误**
```python
class LLMError(Exception):
    code: str  # auth/rate_limit/timeout/context_overflow/content_blocked/unsupported
    retryable: bool
    provider_raw: dict
```

| Provider | 差异 |
|---|---|
| OpenAI 兼容 | 大多数国产模型 |
| Anthropic | messages、thinking、tool use |
| Azure | deployment、api-version |
| 自建 vLLM | 能力有限，需覆盖 |
| 网关 | 错误/用量映射 |

## 6. 配额池算法

### 6.1 参数

| 参数 | 含义 |
|---|---|
| configured_tpm | 每分钟补充 token |
| burst_seconds | 突发容量 = tpm/60 × burst |
| cache_ratio | 缓存命中 token 折算比例（0–1） |
| max_admission_wait_ms | 最大等待 |
| max_waiter_count | 最大排队请求 |
| max_waiting_tokens | 最大等待预占 |
| mode | OBSERVE/ENFORCE |

### 6.2 计算

```
effective = prompt_tokens × (1 - cache_hit_ratio × (1 - cache_ratio))
refill = elapsed_seconds × tpm / 60
bucket = min(capacity, bucket + refill)
if bucket >= effective: admit, bucket -= effective
elif mode == OBSERVE: admit, record would_wait
elif waiters < max_waiters and waiting_tokens + effective <= max_waiting_tokens:
    enqueue (wait <= max_wait_ms)
else: reject 429 quota_exceeded
```

### 6.3 原子性

Redis Lua：

```lua
-- KEYS[1]=bucket, KEYS[2]=waiters
-- ARGV: now, tpm, capacity, need, mode, max_waiters, max_waiting
local b = tonumber(redis.call('HGET', KEYS[1], 'tokens') or capacity)
local last = tonumber(redis.call('HGET', KEYS[1], 'ts') or now)
local refill = math.max(0, (now - last) * tpm / 60)
b = math.min(capacity, b + refill)
if b >= need then
  redis.call('HSET', KEYS[1], 'tokens', b - need, 'ts', now)
  return 1
end
-- observe/enforce/queue...
```

**规则**：使用 Redis 服务端时间；大池按 shard 分桶；快照 + 对账；OBSERVE 记录本应拒绝。

## 7. 模式

| 模式 | 说明 | 适用 |
|---|---|---|
| 直连 Provider | 简单 | 单供应商 |
| 统一网关 | 多供应商/配额/计费 | 推荐 |
| OBSERVE | 只观测不拦截 | 上线前校准 |
| ENFORCE | 强制准入 | 成本控制 |
| 共享池 | 多模型共享 TPM | 同租户 |
| 独占池 | 单模型 | 大客户/关键业务 |
| 同步流式 | SSE | 对话 |
| 非流式 | 阻塞 | 系统调用 |
| 降级 | 备用模型 | 故障 |
| 缓存 | Prompt caching | 长提示词 |

## 8. 路由与降级

```
显式模型 → 可用性/能力 → 配额 → 调用
未指定 → Agent 默认 → 备用 → 全局默认
```

| 场景 | 策略 |
|---|---|
| 429 | 排队/等待 → 备用 → 报错 |
| 5xx | 重试 1 次 → 备用 |
| 超时 | 缩短输出/切模型 |
| 上下文超限 | 裁剪 → 长上下文模型 |
| 能力不支持 | 明确报错 |
| 内容拦截 | 安全提示 |

**熔断**：错误率 > 30%/1min → 打开 30s → 半开。

## 9. 计费

```
cost = (prompt_tokens - cached_tokens) × price_input/1k/1000
     + cached_tokens × price_cache/1k/1000
     + completion_tokens × price_output/1k/1000
```

- 按调用时单价快照；价格变更不影响历史。
- 每次调用落明细；按用户/Agent/模型/会话聚合。
- 与供应商账单按天对账；差异 > 阈值告警。

## 11. 失败与安全

| 场景 | 行为 |
|---|---|
| 密钥无效 | 401 → 配置错误提示 |
| 配额拒绝 | 429 + reset + 建议 |
| 供应商故障 | 熔断/备用/告警 |
| 价格变更 | 新调用新价；旧账单不变 |
| 删除模型 | 展示影响 → 解绑 → 软删 |
| 密钥轮换 | 双版本过渡；旧值失效 |

**安全**：密钥加密（KMS+Vault）；只在网关解密；日志不记录 prompt/密钥；沙箱只拿短期代理 token。

## 14. 代码骨架

```python
async def chat(cfg, req, tenant):
    decision = await quota.admit(cfg.pool_id, req.estimated_tokens, tenant)
    if not decision.admitted:
        raise QuotaExceeded(decision.reset_at)
    try:
        async for chunk in provider.chat(req):
            yield chunk
    except LLMError as e:
        if e.retryable and cfg.fallback_id:
            async for chunk in fallback(cfg.fallback_id, req): yield chunk
        else:
            raise
    finally:
        await usage.record(cfg, req, chunk.usage)
```
