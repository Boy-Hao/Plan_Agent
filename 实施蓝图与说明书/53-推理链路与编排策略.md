# 53 推理链路与编排策略

> 问题：LLM、Skills、MCP 都配好之后，Runtime 到底按什么链路「思考」？
> 答案：不是把工具全丢给模型，而是一条**分层、可观测、有预算、可中断**的推理流水线。

---

## 1. 总链路（10 层）

```
请求
 1. 归一化/鉴权/租户/会话
 2. 意图识别 + 安全前置
 3. 上下文组装（Prompt/变量/引用/附件/历史）
 4. 能力发现（内置工具/Skill/MCP）
 5. 模型路由（能力/成本/延迟/配额）
 6. 规划（直接回答 / ReAct / Plan-Execute / 多 Agent）
 7. 执行循环（LLM → 工具 → 观察 → 继续）
 8. 反思/校验（引用/结构/安全/事实）
 9. 答案合成（格式/引用/产物）
10. 持久化 + 事件 + 用量 + 调用链
```

**原则**：前 5 层是「准备」，第 6 层决定「怎么想」，第 7 层是「做」，第 8 层是「检查」，第 9–10 层是「交付与留痕」。

---

## 2. 第 1 层：归一化

- 校验 token/租户/会话归属。
- 获取会话锁（同会话单活跃轮）。
- 记录 `client_message_id` 幂等。
- 加载 Agent 配置快照（避免运行中变更）。
- 解析来源：Web/飞书/A2A/Blocking/Embed。

**输出**：`TurnContext`（tenant/user/agent/session/source/预算）。

---

## 3. 第 2 层：意图与安全前置

### 3.1 意图分类

| 意图 | 判定 | 走向 |
|---|---|---|
| 闲聊/简单问答 | 短、无工具需求 | 直接回答 |
| 知识问答 | 需要引用/文档 | 引用源 + RAG |
| 业务查询 | 需要业务系统 | Skill/MCP/HTTP |
| 文件处理 | 有附件 | 解析 + 工具 |
| 代码任务 | 需要执行/仓库 | 沙箱 + Git |
| 多步任务 | 复杂/长 | 规划 + 子 Agent |
| 高风险操作 | 删/发/提 MR | 人工确认 |

**实现**：规则优先（关键词/附件/来源），小模型兜底；不要全部交给大模型。

### 3.2 安全前置

- Prompt 注入检测（直接/间接）。
- 敏感数据识别（PII/密钥）。
- 高风险意图标记（外发/删除/支付/权限）。
- 命中 → 拒答/脱敏/转人工。

---

## 4. 第 3 层：上下文组装

### 4.1 层级（高 → 低）

1. 平台安全策略（不可覆盖）
2. Agent 系统提示词
3. 业务模板（biz_id）
4. 引用源（用户选择）
5. 附件摘要/正文
6. 历史（窗口 + 摘要）
7. 当前输入

### 4.2 预算

| 内容 | 预算 |
|---|---|
| 系统提示词 | 固定，超长警告 |
| 历史 | 按 token 窗口 + 摘要 |
| 引用源 | 条数/字符上限 |
| 附件 | 解析摘要；图片多模态 |
| 工具结果 | 单条/总上限；大结果落 OSS |

**原则**：先保证「当前任务」；历史可压缩；引用可裁剪；工具结果只回填必要字段。

---

## 5. 第 4 层：能力发现

### 5.1 工具来源

| 来源 | 发现方式 | 过滤 |
|---|---|---|
| 内置工具 | 注册表 | 权限/开关 |
| Skill | Agent 绑定 | 版本/启用/沙箱/权限 |
| MCP | Agent 配置 | 启停/工具暴露/健康 |
| 业务 HTTP | 工具配置 | 权限/白名单 |

### 5.2 过滤顺序

```
全部工具
→ 权限（用户/Agent/租户）
→ 能力（模型是否支持 tool calling）
→ 可用性（Skill 启用/MCP 健康/沙箱可用）
→ 暴露范围（all/selected）
→ 数量上限（如 ≤30）
→ 生成工具描述
```

### 5.3 工具描述策略

- 名称稳定、语义清晰、避免冲突（加前缀）。
- 参数 JSON Schema 完整；必填/枚举/范围。
- 描述只写「何时用/不用」，不写长篇文档。
- 长说明按需加载（点击/工具帮助），不进入上下文。
- 工具太多时按意图/领域筛选，而不是全量塞入。

**反模式**：把 100 个工具全丢给模型 → 选择困难、token 爆炸、误调用。

---

## 6. 第 5 层：模型路由

### 6.1 路由维度

| 维度 | 说明 |
|---|---|
| 能力 | 工具/视觉/思考/JSON/上下文长度 |
| 任务 | 闲聊/代码/分析/长文 |
| 成本 | 单价 × 预估 token |
| 延迟 | 首 token/总时长 |
| 配额 | 池余额/排队 |
| 可用性 | 熔断/错误率 |
| 合规 | 数据分级/地域 |

### 6.2 策略

```
显式模型 → 能力校验 → 配额准入 → 调用
未指定 → Agent 默认 → 任务路由 → 备用 → 全局默认
```

- 简单任务用小模型；复杂任务用大模型。
- 上下文超限 → 裁剪或长上下文模型。
- 供应商故障 → 熔断 + 备用。
- 高风险/敏感 → 私有化模型（如要求）。

---

## 7. 第 6 层：规划模式

### 7.1 直接回答（Fast Path）

- 无工具/无附件/简单问答。
- 一次 LLM 调用。
- 适合：闲聊、改写、翻译、简单解释。

### 7.2 ReAct（默认）

```
Thought → Action(tool) → Observation → Thought → ... → Answer
```

- 适合：1–5 步工具调用。
- 限制：最大轮次/工具数/时长。
- 每步记录决策与结果。

### 7.3 Plan-and-Execute

```
Planner 生成步骤 → 逐步执行 → 必要时重规划 → 汇总
```

- 适合：多步、依赖、可并行。
- 计划是结构化 JSON，可展示/恢复。
- 失败可重试/跳过/重规划。

### 7.4 多 Agent（Supervisor）

```
Supervisor 拆任务 → 派发子 Agent → 收集摘要 → 汇总
```

- 适合：复杂、跨领域、长任务。
- 子 Agent 独立上下文/预算。
- 父只收摘要 + 产物引用。

### 7.5 Human-in-the-Loop

- 高风险工具、权限不足、授权缺失。
- 暂停 → 提示 → 用户确认/授权 → 恢复。
- 记录谁批准、何时、什么操作。

### 7.6 模式选择

| 条件 | 模式 |
|---|---|
| 无工具 | 直接回答 |
| 1–5 步工具 | ReAct |
| 多步/可并行 | Plan-Execute |
| 跨领域/长任务 | 多 Agent |
| 高风险 | Human-in-the-loop |
| 需要严格格式 | 结构化输出 + 校验 |

## 8. 第 7 层：执行循环

```python
for step in range(max_turns):
    resp = llm.chat(messages, tools=available_tools)
    if resp.tool_calls:
        for call in resp.tool_calls:
            validate(call)               # schema/permission/risk
            result = execute(call)       # timeout/retry/cancel
            messages.append(tool_result(result))
        continue
    return resp.content
raise MaxTurnsExceeded()
```

**规则**
- 工具调用前：权限、参数、配额、风险。
- 只读可并行；写串行；高危需确认。
- 结果脱敏/截断；失败返回结构化错误给模型。
- 检测循环（相同工具+参数重复）。
- 预算耗尽 → 停止并返回部分结果。

---

## 9. 第 8 层：反思与校验

| 校验 | 说明 |
|---|---|
| 引用 | 知识问答必须有来源；无来源标注不确定 |
| 结构 | JSON Schema 校验；失败重试/修复 |
| 事实 | 关键数字/日期/名称交叉检查（可选） |
| 安全 | 输出审核/脱敏/拒答 |
| 一致性 | 与工具结果/引用源一致 |
| 完整性 | 是否回答用户问题/满足格式 |

**反思模式**：轻量（规则/模板）优先；复杂任务可二次 LLM 校验；不要每轮都反思（成本）。

---

## 10. 第 9 层：答案合成

- 结构：结论 → 依据 → 明细 → 下一步。
- 引用：`[1]` 标注来源/链接。
- 产物：表格/图表/文档/代码，放 artifact。
- 格式：Markdown；代码块；表格。
- 语气：简洁、可执行；不确定要说明。
- 敏感：脱敏；高风险加免责声明。

---

## 11. 第 10 层：持久化与事件

- 消息（最终内容 + 摘要）。
- 用量（prompt/completion/cached/cost）。
- 调用链（LLM/工具/子 Agent）。
- 审计（高危操作）。
- SSE 事件（`msg_end`）。
- 反馈入口。

---

## 12. 三条典型链路

### 12.1 知识问答

```
意图=知识 → 引用源选择 → 检索/查询 → 上下文注入
→ 直接回答（要求引用）→ 校验来源 → 输出
```

### 12.2 业务查询 + Skill/MCP

```
意图=业务 → 能力发现（Skill/MCP）→ ReAct
→ 调 MCP 查询 → 观察 → 调 Skill 校验 → 汇总
→ 输出表格 + 依据
```

### 12.3 代码任务

```
意图=代码 → 沙箱检查/创建 → 读仓库 → 计划
→ 改代码 → 跑测试 → 失败修复 → 生成 diff
→ 人工确认 → 提交/MR → 输出链接
```

---

## 13. 失败与恢复

| 失败 | 处理 |
|---|---|
| 意图误判 | 允许用户纠正/重试；记录 badcase |
| 工具选错 | 模型观察错误后重选；限制重试 |
| 工具超时 | 返回超时；模型决定继续/换工具 |
| 上下文超限 | 裁剪/摘要/换模型 |
| 模型 429 | 排队/备用/提示 |
| 循环 | 检测相同调用；强制停止 |
| 预算耗尽 | 返回部分结果 + 说明 |
| 高风险未确认 | 暂停等待 |
| 取消 | 传播到 LLM/工具/子 Agent |

---

## 14. 可观测与优化

**每次决策记录**：
- 意图/路由/模型/工具/参数/结果/耗时。
- 为什么选这个工具（可解释）。
- 预算使用。
- 失败原因。

**指标**：任务完成率、工具准确率、平均轮次、首 token、单任务成本、循环率、人工介入率。

**优化**：badcase → Prompt/Skill/MCP 描述/路由策略 → 回归评测。

---

## 15. 反模式

| 反模式 | 后果 | 纠正 |
|---|---|---|
| 全量工具塞上下文 | 选择困难/贵 | 按意图筛选 |
| 系统提示词巨长 | 贵/漂移 | 分层/模板 |
| 每轮都反思 | 慢/贵 | 关键节点校验 |
| 让模型决定权限 | 越权 | 工具层强校验 |
| 无预算 | 无限循环 | 轮次/时间/成本 |
| 无调用链 | 无法排障 | Trace |
| 失败静默 | 用户困惑 | 明确提示/降级 |
| 多 Agent 过度使用 | 成本/复杂 | 单 Agent 优先 |

## 16. 验收标准

- [ ] 每次请求都经过 10 层链路（可观测）。
- [ ] 工具按权限/能力/可用性过滤，不超上限。
- [ ] 模型路由可解释（能力/成本/配额）。
- [ ] 单/多 Agent/Plan 模式可切换。
- [ ] 高风险工具有人工确认。
- [ ] 预算/循环/取消有效。
- [ ] 答案有引用/校验。
- [ ] 失败有明确提示与恢复。
- [ ] 调用链可定位到每次决策。
