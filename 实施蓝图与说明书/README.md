# 实施蓝图与说明书

> 目标：让一个 8–10 人团队，按本手册**快速搭出一个可用的云端智能体平台**，而不是只停留在架构图。
> 本目录回答三件事：**怎么搭、每个模块怎么实现、每种模式怎么选/怎么配/怎么验收。**

1. 先看「职责与边界」，确认不重复造轮子。

4. 看「失败/安全/观测」，补生产级细节。
5. 按「验收标准」写测试。

## 2. 快速构建的总体策略

### 2.1 先骨架，后模块，再模式

```
Week 0–1：仓库骨架 + docker compose + 登录 + 健康检查
Week 2–4：Agent + 模型 + 会话 SSE（最小闭环）
Week 5–8：Skill + 文件 + 沙箱 + 配额
Week 9–12：权限/审计/集成/部署/压测
```

**不要**先做多 Agent、权限审计、OSS 治理；这些是 P2。

### 2.2 模块化单体 + 两个独立进程

```
control-plane (FastAPI, 模块化单体)
agent-runtime (FastAPI/异步, 独立进程)
sandbox-worker (独立进程/节点池)
MySQL + Redis + OSS
```

首版不拆微服务；模块边界用目录 + import-linter 保证。

### 2.3 一套模板复用

`templates/` 提供：

- `docker-compose.yml`：本地 MySQL/Redis/MinIO/后端/前端
- `.env.example`：全部环境变量
- `schema.sql`：核心表 DDL（可先跑）
- `helm-values.yaml`：K8s 部署基线
- `Makefile`：常用命令
- `nginx.conf`：前后端代理/SSE 配置

## 5. 模块 Definition of Done（DoD）

每个模块完成必须满足：

- [ ] 领域模型/表/索引/迁移
- [ ] API + OpenAPI + 错误码
- [ ] 权限点 + 资源 ACL
- [ ] 单元/集成/契约测试
- [ ] 指标/日志/Trace
- [ ] 失败/降级/超时
- [ ] 配置项 + 默认值
- [ ] 文档（模块说明 + 运维 Runbook）
- [ ] 演示脚本（可重复）
- [ ] 安全评审（如涉及密钥/执行）

## 6. 三种「快速」的边界

| 快速方式 | 能省什么 | 不能省什么 |
|---|---|---|
| 用模板/脚手架 | 目录、配置、CI | 领域规则、权限、测试 |
| 用托管服务 | 运维、扩容 | 数据隔离、成本、合规 |
| 用开源框架 | 编排、UI | 一致性、可观测、安全 |

**结论**：可以用模板和托管加速，但**权限、流式一致性、配额、沙箱隔离**必须自己设计。
