# 27 可扩展性与容量架构

## 1. 容量模型（先算再建）

### 1.1 输入变量

| 变量 | 含义 | 示例 |
|---|---|---|
| DAU | 日活用户 | 1,000 / 10,000 |
| TPD | 人均日轮次 | 10 |
| C | 峰值并发会话比例 | 5%–10% |
| T | 单轮平均时长 | 20s |
| P | 平均输入 token | 6k |
| O | 平均输出 token | 800 |
| S | 平均会话消息数 | 20 |

### 1.2 关键公式

```
日轮次 = DAU × TPD
峰值并发轮次 ≈ DAU × TPD / 86400 × 峰值系数(3–5)
峰值 SSE 连接 ≈ 峰值并发轮次 × 1.2
日输入 token = 日轮次 × P
日输出 token = 日轮次 × O
日 DB 消息写 = 日轮次 × 2（user + assistant）
日用量记录 = 日轮次 × 平均 LLM 调用次数
沙箱并发 ≈ 日轮次 × 沙箱使用率 × 平均时长 / 86400
```

### 1.3 示例（1,000 DAU）

```
日轮次 = 10,000
峰值并发 ≈ 10,000/86400 × 4 ≈ 0.46 → 实际按 50–100 并发设计
日输入 = 60M token；日输出 = 8M token
日消息写 = 20,000 行
日用量记录 ≈ 20,000–60,000 行
```

> 注意：并发不是「DAU/86400」这么简单，要看使用时段集中度；企业用户集中在工作时间，峰值系数取 3–5 更现实。

## 2. 扩展维度

| 组件 | 扩展方式 | 上限/瓶颈 |
|---|---|---|
| API（Control Plane） | 无状态多副本 + HPA | DB 连接、慢查询 |
| Runtime | 无状态多副本 + 队列 | 模型 TPM、内存（上下文） |
| SSE Gateway | 按连接数扩 + 独立节点池 | 内存/文件描述符/网络 |
| Worker | 按队列长度扩（KEDA） | 外部 API 限流 |
| Sandbox Worker | 节点池 + 调度 | 节点容量/镜像拉取 |
| MySQL | 读写分离 + 分区 + 分库 | 写放大、大表 |
| Redis | Cluster + 分片 | 热 key、内存 |
| OSS | 无限（按前缀） | 流量/成本 |
| 模型 | 多 Provider + 配额池 | 供应商 TPM |

---

## 3. 瓶颈排序（按先崩顺序）

1. **MySQL 写入**：每 token 写库会瞬间打满；必须批量/异步。
2. **Redis 热 key**：单会话锁/单配额池；用分片/本地缓存。
3. **SSE 内存**：每连接缓冲；用独立网关 + 批量合并。
4. **模型 TPM**：供应商限额；多供应商/降级。
5. **沙箱供给**：创建慢/节点不足；预热/自动扩缩。
6. **上下文组装**：大历史/引用源；摘要/裁剪/缓存。
7. **审计/日志**：全量长保留；采样/分层/归档。

## 4. 数据库扩展

### 4.1 写优化

- 消息/用量批量插入（如 50–100 条/批），减少事务开销。
- 流式 token 不写库；只在 `msg_end` 写最终内容 + 摘要。
- 工具结果大内容落 OSS，DB 存引用。
- 用量异步聚合，明细按月分区。

### 4.2 分区/分表

| 表 | 策略 |
|---|---|
| message | 按 `session_id` hash 或按月 + session 二级 |
| usage_llm_call | 按月分区 |
| audit_log | 按月分区，冷归档 |
| notification | 按用户 + 时间 |
| file_reference | 按 file_id hash |

### 4.3 读写分离

- 列表/报表走只读副本；强一致读走主库。
- 复制延迟敏感场景（刚写完立即读）强制主库。
- 报表/分析走独立只读实例或数仓，避免影响交易。

### 4.4 分库触发

- 单表 > 5 亿行或写入 > 5k TPS。
- 主库 CPU > 70% 持续。
- 备份/DDL 窗口不可接受。
- 按租户/会话 hash 分库；先做逻辑分片（sharding key 路由）。

## 5. 缓存架构

```
Browser
  ↓
CDN (static)
  ↓
API local LRU (config, permissions)
  ↓
Redis (shared cache, locks, quota, SSE)
  ↓
MySQL
```

| 数据 | 缓存 | TTL | 失效 |
|---|---|---|---|
| 权限 | 本地 + Redis | 10 min | 角色变更主动删 |
| Agent 配置 | Redis | 5 min | 更新删 key |
| 模型配置 | 本地 | 1 min | 更新广播 |
| Skill 元数据 | Redis | 10 min | 版本变更删 |
| 配额 | Redis（源） | — | Lua 原子 |
| 会话列表 | 可选 | 30s | 写后删 |

**防击穿**：singleflight/互斥重建；空值缓存 30s；随机 TTL。
**防热 key**：key 加 shard 后缀；本地缓存；读写分离。
**防雪崩**：TTL 抖动；降级返回旧值；熔断。

## 6. SSE 扩展

- 独立 `sse-gateway` 部署，不与 API 混部。
- 每连接内存预算（如 16–32KB），按节点内存算连接上限。
- 事件批量合并（30–60ms）降低写放大。
- 心跳 15s；空闲连接回收。
- 多副本通过 Redis Pub/Sub；ring buffer 存 Redis Stream。
- 连接数超过阈值：拒绝新连接/排队/提示。

**估算**：单节点 8GB，扣除系统 2GB，每连接 32KB → 理论上限 ~18 万；实际按 5–8 万设计，留余量。

## 7. 模型容量

| 指标 | 计算 | 动作 |
|---|---|---|
| 所需 TPM | 日输入/输出 token / 峰值小时占比 | 配额池配置 |
| 并发请求 | 峰值并发轮次 × 平均工具轮次 | Provider 并发限额 |
| 429 率 | 拒绝/总请求 | 扩容/降级/排队 |
| 首 token | 网络+排队+模型 | 路由到低延迟模型 |

**策略**
- 多 Provider 按能力/成本/延迟路由。
- 配额池 OBSERVE 校准后再 ENFORCE。
- 高峰优先交互式，后台任务降级/排队。
- 失败切换备用，记录降级率。

## 8. 沙箱容量

```
沙箱并发 = 日任务数 × 平均时长 / 86400 × 峰值系数
节点数 = 沙箱并发 × 单沙箱资源 / 节点资源 / 目标利用率(0.7)
预热池 = 峰值并发 × 10%–20%
```

- 模板越小启动越快；镜像预拉取。
- 空闲暂停/销毁；共享池提升利用率。
- 节点池自动扩缩；大促前预热。
- 创建失败率 > 5% 告警。

## 9. 负载保护

| 机制 | 说明 |
|---|---|
| 入口限流 | IP/用户/租户 QPS、并发连接 |
| 优先级 | 交互式 > 后台任务 > 批量 |
| 准入控制 | 配额/沙箱/队列满时拒绝 |
| 背压 | 生产快于消费时合并/丢弃旧 token |
| 熔断 | 依赖错误率高时快速失败 |
| 降级 | 关闭非核心功能（如调用链、思考） |
| 排队 | 429 + Retry-After；前端提示 |

**原则**：宁可明确拒绝，不要拖垮全站。

## 10. 多地域

| 模式 | 适用 | 注意 |
|---|---|---|
| 单地域多 AZ | 首版 | 成本低，容灾够 |
| 主备地域 | 合规/容灾 | 数据复制、切换演练 |
| 双活 | 全球化/低延迟 | 数据一致性、冲突 |
| 数据驻留 | 合规 | 按租户路由 |

**建议**：首版单地域多 AZ；有跨境/合规需求再做数据驻留，不要过早双活。

## 11. 压测与容量验证

| 场景 | 目标 |
|---|---|
| 200 并发对话 | 错误 < 1%，首 token P95 ≤ 3s |
| 5k SSE 连接 | 内存/CPU 稳定，断连 < 0.1% |
| 100 并发沙箱 | 创建 P95 ≤ 10s |
| 1 万条/秒事件 | Redis/网关不丢 |
| 1 亿消息查询 | 分页 P95 ≤ 500ms |
| 故障切换 | RTO ≤ 30min |

**方法**：基线 → 阶梯加压 → 找拐点 → 优化 → 回归；记录每次版本基线。
