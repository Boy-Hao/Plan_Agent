# 28 高可用与故障降级矩阵

## 1. 目标

- 任何单点故障不导致全站不可用。
- 依赖故障时，用户看到**明确、可理解**的降级，而不是白屏/转圈。
- 故障可检测、可止损、可恢复、可复盘。

---

## 2. 故障域

| 故障域 | 影响 | 隔离手段 |
|---|---|---|
| 可用区 | 部分实例/DB | 多 AZ、反亲和 |
| 节点 | 单节点 Pod | 多副本、PDB |
| 服务 | 某服务全挂 | 熔断、降级、限流 |
| 依赖 | DB/Redis/模型/沙箱 | 超时、重试、备用 |
| 租户 | 单租户流量/数据 | 配额、隔离池 |
| 会话 | 单会话异常 | 锁、超时、清理 |
| 变更 | 发布/配置错误 | 灰度、回滚、特性开关 |

---

## 3. 依赖故障矩阵

| 依赖 | 故障表现 | 影响 | 检测 | 降级 | 恢复 |
|---|---|---|---|---|---|
| SSO | 登录失败 | 新用户无法进 | 登录成功率 | 已有会话继续；提示稍后 | IdP 恢复 |
| MySQL | 查询/写入失败 | 全站读写出错 | 连接/错误率 | 只读缓存；拒绝写；提示 | 主从切换 |
| Redis | 锁/SSE/配额异常 | 对话/续传/限流异常 | ping/延迟 | SSE 降级；锁降级为 DB；配额保守拒绝 | 重启/切主 |
| 模型 Provider | 429/5xx/超时 | 对话失败/变慢 | 错误率/延迟 | 备用模型/排队/提示 | 供应商恢复 |
| Sandbox | 创建/执行失败 | 代码任务不可用 | 创建失败率 | 只读工具；提示稍后 | 节点恢复 |
| OSS | 上传/下载失败 | 附件/Skill 不可用 | 错误率 | 重试；禁用上传 | OSS 恢复 |
| 飞书 | WS 断/发送失败 | IM 入口/推送不可用 | WS 状态/发送失败率 | 重连；Web 入口可用 | 重连成功 |
| GitLab | API 失败 | 同步/MR 不可用 | 错误率 | 重试；只读 | 恢复 |

---

## 4. 降级等级

| 等级 | 定义 | 用户可见 | 触发 |
|---|---|---|---|
| L0 正常 | 全功能 | — | — |
| L1 轻度 | 关闭非核心（调用链、思考、图表） | 部分入口隐藏 | 依赖延迟升高 |
| L2 中度 | 关闭写操作/沙箱/集成 | 提示「暂时不可用」 | 依赖错误率高 |
| L3 重度 | 只读/维护页 | 明确公告 | 核心依赖不可用 |
| L4 灾难 | 全站不可用 | 维护页 | 多 AZ/数据损坏 |

**原则**：降级要**自动触发 + 可手动强制**；恢复要**渐进**，避免雪崩。

---

## 5. 超时预算

```
Client 60s
  └─ Gateway 55s
      └─ API 50s
          └─ Runtime 45s
              ├─ Context build 2s
              ├─ LLM first token 30s
              ├─ Tool 30s（可配）
              └─ Persist 5s
```

- 上游超时 > 下游总和，避免「父先超时、子还在跑」。
- 每层有独立超时；不允许无限等待。
- 重试预算：单请求最多 1 次重试（幂等），避免放大。

---

## 6. 熔断与重试

| 依赖 | 熔断阈值 | 半开 | 重试 |
|---|---|---|---|
| 模型 | 错误率 > 30%（1min） | 30s | 1 次 + 备用 |
| 沙箱 | 创建失败 > 20% | 60s | 1 次 |
| 飞书 | 发送失败 > 20% | 60s | 1 次 |
| GitLab | 5xx > 20% | 60s | 1 次 |
| OSS | 5xx > 20% | 30s | 2 次 |

**重试原则**：只重试幂等请求；带 jitter；不超过总超时；记录重试次数。

---

## 7. 数据层高可用

| 组件 | 方案 | RPO | RTO |
|---|---|---|---|
| MySQL | 主从 + 半同步 + 自动切换 | ≤ 15s | ≤ 5min |
| Redis | Cluster/Sentinel + AOF | ≤ 1s | ≤ 1min |
| OSS | 多副本/跨区复制 | ≈ 0 | 分钟级 |
| 消息队列 | 持久化 + 副本 | ≤ 1s | ≤ 1min |

- 定期故障切换演练；切换后校验数据。
- 避免「脑裂」：仲裁/租约；写操作校验主。
- 备份异地；恢复演练每季度。

---

## 8. 发布与变更故障

| 风险 | 对策 |
|---|---|
| 新版本 bug | 金丝雀 5% → 25% → 100% |
| 配置错误 | 版本化 + 审批 + 一键回滚 |
| 迁移失败 | 备份 + 预检 + 可回滚 |
| 模型切换 | 灰度 + 对比评测 + 快速回切 |
| 配额参数错误 | OBSERVE 先行 + 版本确认 |

**自动回滚**：错误率/延迟/断连超阈值 → 自动回滚并告警。

---

## 9. 混沌演练

| 实验 | 期望 |
|---|---|
| 杀 API Pod | 请求不中断（多副本） |
| Redis 主节点故障 | 锁/SSE 降级，自动恢复 |
| MySQL 主从切换 | 写入短暂失败，恢复后一致 |
| 模型 429 持续 5min | 切换备用，用户有提示 |
| 沙箱节点下线 | 任务重试/迁移，失败可见 |
| 网络延迟 500ms | 超时/熔断生效，不雪崩 |
| 磁盘满 | 日志/临时文件清理，告警 |

**频率**：每季度一次；大促前一次；记录改进项。

## 10. Runbook 模板

```
【故障】<名称>
【影响】<用户/功能/地域>
【检测】<指标/告警>
【止损】1... 2... 3...
【定位】<看板/Trace/日志/最近变更>
【恢复】<步骤>
【验证】<核心链路>
【复盘】<时间线/根因/改进>
```

### 示例：模型 429 飙升

1. 看板确认 Provider/模型/租户。
2. 开启备用模型路由；降低后台任务优先级。
3. 对非核心请求返回 429 + Retry-After。
4. 联系供应商扩容；观察恢复。
5. 复盘：配额/路由/重试策略。
