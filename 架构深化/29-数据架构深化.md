# 29 数据架构深化

## 1. 数据架构原则

1. **一个数据一个 Owner**：每个上下文拥有自己的表，其他上下文只引用 ID。
2. **强一致在聚合内，最终一致跨聚合**：不追求全局事务。
3. **写少读多**：配置缓存、读模型、报表分离。
4. **可删除、可导出、可审计**：数据生命周期从第一天设计。
5. **先分区后分库**：优先用时间和 hash 解决大表。

## 2. 数据所有权

| 上下文 | 表前缀/示例 | 读方 |
|---|---|---|
| Identity | `sys_*`、`api_key` | 所有（只读） |
| Agent | `agent*` | Conversation/Runtime |
| Skill | `skill*`、`personal_skill*` | Agent/Conversation |
| Conversation | `session`、`message`、`turn*` | Governance/Analytics |
| Model | `llm_config`、`quota*`、`usage_llm_call` | Conversation/Analytics |
| Execution | `sandbox*`、`git_lease` | Conversation/Admin |
| Integration | `feishu*`、`gitlab*`、`a2a*` | Conversation/Admin |
| Governance | `audit*`、`feedback`、`oss_*` | Admin |

**禁止**：跨上下文 JOIN 写库；共享可变实体；直接改别人的表。

---

## 3. 一致性模型

| 场景 | 一致性 | 机制 |
|---|---|---|
| 创建 Agent + 绑定 | 强一致 | 单事务 |
| 删除 Agent + 解绑 | 强一致 | 单事务 + 影响预览 |
| 消息 + 用量 + 审计 | 最终一致 | Outbox |
| 配额扣减 + 用量 | 最终一致 | Redis 原子 + 对账 |
| 跨服务通知 | 最终一致 | 事件 + 幂等 |
| 报表 | 最终一致 | CDC/ETL |

**原则**：不要用分布式事务；用「本地事务 + 事件 + 幂等 + 对账」。

## 4. Schema 模式

### 4.1 公共字段

```sql
id            VARCHAR(32) PRIMARY KEY,
tenant_id     VARCHAR(32) NOT NULL,
create_time   DATETIME(3) NOT NULL,
update_time   DATETIME(3) NOT NULL,
create_user_id VARCHAR(64),
update_user_id VARCHAR(64),
is_deleted    TINYINT NOT NULL DEFAULT 0,
delete_time   DATETIME(3) NULL
```

### 4.2 版本与乐观锁

```sql
version       INT NOT NULL DEFAULT 1,
config_version INT NOT NULL DEFAULT 1
```

更新：`UPDATE ... SET version=version+1 WHERE id=? AND version=?`；影响行数 0 → 409。

### 4.3 软删除

- 查询默认 `is_deleted=0`。
- 唯一性在应用层校验（范围内），不建 DB UNIQUE。
- 删除后保留引用，避免级联破坏。

### 4.4 大字段

- 消息正文可 `TEXT/MEDIUMTEXT`；超长/附件落 OSS。
- 工具结果/调用链大内容落 OSS，DB 存 `object_key` + 摘要。
- JSON 只存低频查询的扩展字段；高频字段拆列。

## 5. 索引与查询

| 查询 | 索引 |
|---|---|
| 会话列表 | `(tenant_id, user_id, is_deleted, last_active_time DESC)` |
| 消息分页 | `(tenant_id, session_id, seq)` |
| 用量按时间 | `(tenant_id, create_time)` |
| 用量按 Agent | `(tenant_id, agent_id, create_time)` |
| 反馈 | `(tenant_id, agent_id, create_time)` |
| 审计 | `(tenant_id, resource_type, resource_id, create_time)` |
| 通知 | `(tenant_id, user_id, read_status, create_time DESC)` |

**规则**
- 联合索引遵循最左前缀；区分度高在前。
- 避免 `%keyword%`；搜索用 OpenSearch。
- 分页用游标（`last_id/last_time`）而非大 offset。
- 慢查询阈值 200ms；每周审查。

## 6. 分区与归档

| 表 | 分区键 | 保留 | 归档 |
|---|---|---|---|
| message | 月 + session hash | 1–3 年 | OSS/冷库 |
| usage_llm_call | 月 | 2 年 | 聚合后删明细 |
| audit_log | 月 | ≥1 年 | WORM/冷存储 |
| notification | 月 | 1 年 | 删除 |
| trace | 天 | 30–90 天 | 采样 |

**归档流程**：标记 → 导出 → 校验 → 删除；保留查询入口（冷数据）。

## 7. Redis 数据结构

| 用途 | 结构 | 说明 |
|---|---|---|
| 会话锁 | String + Lua | `SET NX PX`，fencing token |
| 活跃轮 | Hash | `message_id/status/updated_at` |
| SSE log | Stream | `XADD`，`MAXLEN` 限制 |
| SSE live | Pub/Sub | 实时广播 |
| 配额桶 | Hash + Lua | tokens/last_refill |
| 排队 | ZSet/List | 等待请求 |
| 权限缓存 | String(JSON) | TTL |
| 未读数 | String/Hash | 原子增减 |
| 限流 | String + Lua | 滑动窗口/令牌桶 |
| 幂等 | String | `SET NX EX` |

**内存估算**：SSE 连接 × 缓冲 + Stream 长度 × 事件大小 + 配额池数量 × 小对象。按峰值 1.5 倍预留。

## 8. 分析/报表

```
MySQL (OLTP) → CDC (Debezium/Canal) → Kafka → 数仓/湖
                                      → 实时聚合 (Flink)
                                      → BI/看板
```

- 交易与分析分离，避免报表拖垮主库。
- 指标口径统一（token、费用、会话、活跃）。
- 日/小时聚合表；明细保留 90 天。
- 数据质量校验（行数、金额、去重）。

**首版**：可用只读副本 + 定时聚合，不必上完整数仓。

## 9. 数据生命周期

| 数据 | 创建 | 保留 | 删除 |
|---|---|---|---|
| 会话/消息 | 用户对话 | 1–3 年 | 软删 → 归档 → 物理 |
| 附件 | 上传 | 随会话/30 天回收站 | 生命周期 |
| 用量明细 | 调用 | 2 年 | 聚合后删 |
| 审计 | 操作 | ≥1 年 | 归档 |
| Trace | 请求 | 30–90 天 | 采样 |
| 沙箱工作目录 | 任务 | 任务结束 | 立即清理 |
| 导出 | 管理端 | 7 天 | 定时清理 |

**删除权**：用户可删自己的；管理员合规删除；全部审计。

## 10. 零停机迁移

```
1. 扩展：加新列/新表（可空/双写）
2. 回填：后台任务分批
3. 双读：读新+旧，对比
4. 切换：读新，写新
5. 收缩：停旧写，删旧列
```

- 每步可回滚；大表用 online DDL/gh-ost。
- 迁移前备份；迁移后校验。
- 禁止在高峰期做锁表操作。

## 11. 容量估算（示例）

| 数据 | 1 万 DAU/年 | 说明 |
|---|---|---|
| 消息 | 1 万 × 10 × 2 × 365 ≈ 7,300 万行 | 含 user/assistant |
| 用量 | × 2–3 次 LLM ≈ 1.5–2 亿行 | 按月分区 |
| 审计 | 操作量级 | 按月 |
| 附件 | 按上传率 | OSS |
| Trace | 采样 10% | 保留 30 天 |

**结论**：消息/用量必须分区；否则一年后查询和备份都会痛。
