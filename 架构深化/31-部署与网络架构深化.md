# 31 部署与网络架构深化

## 1. 集群拓扑

```
Region
├─ AZ-a
│  ├─ system node pool（ingress/监控/operator）
│  ├─ app node pool（api/runtime/sse/worker）
│  └─ sandbox node pool（独立账号/网络）
├─ AZ-b（同上）
└─ AZ-c（可选）
```

| 节点池 | 规格 | 污点/标签 | 用途 |
|---|---|---|---|
| system | 4C8G | `role=system` | Ingress、监控、Operator |
| app | 8C16G/16C32G | `role=app` | API/Runtime/SSE/Worker |
| sse | 4C8G（网络优化） | `role=sse` | 长连接 |
| sandbox | 16C64G/32C128G | `role=sandbox:NoSchedule` | 沙箱 |
| gpu（可选） | GPU | `role=gpu` | 私有化模型 |

**原则**：沙箱节点独立账号/安全组/VPC 子网；不与控制面共享节点。

## 2. 命名空间

| Namespace | 内容 | 网络策略 |
|---|---|---|
| `platform-system` | ingress、cert-manager、monitoring | 允许出站 |
| `platform-control` | api、worker | 访问 DB/Redis/OSS |
| `platform-runtime` | runtime、sse-gateway | 访问模型/Redis/DB(只读) |
| `platform-sandbox` | sandbox-worker、sandbox pods | 默认拒绝，白名单 |
| `platform-integration` | feishu/gitlab workers | 访问外网白名单 |
| `platform-observability` | prometheus/loki/tempo | 采集 |

## 3. 网络策略

### 3.1 默认拒绝

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
```

### 3.2 按需放行

| 源 | 目标 | 端口 | 说明 |
|---|---|---|---|
| ingress | api/runtime/sse | 8080 | 入口 |
| api | mysql/redis/oss | 3306/6379/443 | 控制面 |
| runtime | mysql(只读)/redis/model | 3306/6379/443 | 数据面 |
| runtime | sandbox-worker | 8080 | 任务 |
| sandbox | model-proxy/oss | 443 | 白名单 |
| integration | 飞书/GitLab | 443 | 出站白名单 |

**禁止**：sandbox → 控制面 DB/K8s API/元数据/内网任意端口。

---

## 4. 入口与边缘

```
DNS → CDN(static) 
    → WAF → Ingress (TLS) → Service
```

- TLS 终止在 Ingress；证书自动续期。
- WAF：OWASP、CC 防护、IP 黑名单。
- 限流：IP/用户/租户；SSE 单独限。
- 管理端可选 IP 白名单/VPN。
- 静态资源：OSS + CDN，版本目录，长缓存。

---

## 5. 出站与私网

- 统一 **Egress Gateway**：固定 IP、白名单、审计。
- 模型/飞书/GitLab/OSS 通过域名白名单。
- 禁止直接访问公网；禁止访问云元数据。
- 与 IDC/内网通过专线/PrivateLink；不暴露公网。

---

## 6. 配置与密钥

| 类型 | 方式 |
|---|---|
| 非敏感配置 | ConfigMap / 配置中心 |
| 密钥 | External Secrets + Vault/KMS |
| 应用密钥 | DB 密文 + KMS |
| 前端配置 | `/config.json`（无密钥） |
| 特性开关 | Unleash/配置中心 |

- 配置版本化；变更审计；一键回滚。
- 不同环境独立密钥；禁止复用生产密钥。

---

## 7. GitOps 与发布

```
Git (Helm/Kustomize) → Argo CD → Cluster
```

- 环境分支/目录：dev/test/uat/prod。
- 镜像 tag 固定 digest；禁止 latest。
- 发布：金丝雀 → 观察 → 全量；或蓝绿。
- 回滚：Git revert + Argo sync；镜像回滚。
- 数据库迁移独立 Job，先于应用；可回滚。

---

## 8. 可观测流水线

```
App (OTel SDK) → OTel Collector → Prometheus/Loki/Tempo
                                  → Grafana/Alertmanager
```

- 采集：指标、日志、Trace、Profiling（可选）。
- 采样：Trace 10%/错误 100%；日志结构化。
- 告警到飞书/电话；值班轮换。
- 成本：日志分级、保留期、冷存储。

## 9. 多环境

| 环境 | 集群 | 数据 | 外部集成 |
|---|---|---|---|
| dev | 共享 | mock/种子 | mock |
| test | 独立 | 脱敏 | 测试企业 |
| uat | 独立 | 仿真 | 测试企业 |
| prod | 多 AZ | 真实 | 生产 |

- 环境隔离：VPC/账号/DB/Redis/Bucket。
- 禁止测试访问生产。
- 配置/密钥独立。

---

## 10. 容灾拓扑

| 级别 | 方案 |
|---|---|
| 同城多 AZ | 默认；DB/Redis 主从跨 AZ |
| 异地备份 | OSS 跨区 + DB 备份异地 |
| 异地双活 | 仅在有明确 RTO/RPO 需求时 |
| 数据驻留 | 按租户路由到区域 |

**RTO/RPO**：核心 ≤ 30min / ≤ 15s；分析可放宽。

---

## 11. 成本与调度

- 节点池按负载自动扩缩；低峰缩容。
- 沙箱用 Spot/竞价（可中断任务）；关键任务用按需。
- 资源请求/限制合理；避免超卖导致 OOM。
- 监控闲置资源；定期清理。
- 成本按 namespace/租户/团队分摊。
