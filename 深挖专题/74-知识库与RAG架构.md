# 74 知识库与 RAG 架构

## 1. 问题定义

企业知识散落在：飞书文档、Wiki、PDF、Excel、数据库、工单、BOM、代码库、网页。
Agent 要回答「有依据」的问题，需要：

- 把知识**接进来**（接入/解析/切分/索引）；
- 把问题**查得准**（改写/混合检索/重排）；
- 把结果**用得对**（上下文组装/引用/权限）；
- 把效果**评得出**（召回/支撑/引用准确）；
- 把权限**管得住**（文档级/片段级/租户）。

---

## 2. 总体架构

```
数据源（文档/DB/API/网页）
  ↓ Connector
解析/清洗（PDF/Word/Excel/HTML/OCR）
  ↓
切分（结构/语义/父子）
  ↓
Embedding + 关键词索引
  ↓
向量库 + 搜索引擎（混合）
  ↓
检索（改写/多路/过滤/重排/Top-K）
  ↓
上下文组装 + 引用
  ↓
Agent 回答
```

---

## 3. 数据接入

| 数据源 | 方式 | 增量 |
|---|---|---|
| 飞书文档/Wiki | API/导出 | 版本/更新时间 |
| PDF/Word/Excel | 上传/目录 | 文件哈希 |
| 数据库 | 只读查询/CDC | 时间戳/增量 |
| 业务 API | 定时拉取 | 游标 |
| 网页 | 爬取/白名单 | ETag/时间 |
| 代码库 | Git clone/API | commit |

**原则**：每个数据源有 Connector、游标、失败重试、删除同步。

---

## 4. 解析与清洗

| 类型 | 处理 |
|---|---|
| PDF | 文本层/OCR；表格；页码 |
| Word | 段落/标题/表格；样式 |
| Excel | 表头/Sheet/公式值；按行/列 |
| HTML | 正文抽取；去导航/广告 |
| 代码 | 语法树/文件树；注释 |
| 图片 | OCR/多模态描述 |

**清洗**：去噪、去重、统一编码、修复断行、保留结构（标题层级/表格）。

---

## 5. 切分策略

| 策略 | 说明 | 适用 |
|---|---|---|
| 固定长度 | 512–1024 token + overlap | 通用 |
| 结构感知 | 按标题/段落/表格 | 文档 |
| 语义切分 | 句子/语义边界 | 长文 |
| 父子块 | 小块检索、大块上下文 | 精度+上下文 |
| 代码切分 | 函数/类/文件 | 代码 |
| 表格切分 | 表头+行组 | 表格 |

**建议**：默认结构感知 + 512–800 token + 10–15% overlap；问答型用父子块。

**元数据**：doc_id、chunk_id、title、section、page、url、tenant、acl、version、updated_at、hash。

---

## 6. 索引

### 6.1 向量

- 模型：企业可选 bge/e5/text-embedding-3 等；统一维度。
- 归一化；批量；缓存。
- 向量库：Milvus/Qdrant/pgvector/OpenSearch。
- 索引：HNSW/IVF；按租户分区/过滤。

### 6.2 关键词

- BM25/OpenSearch；精确术语/编号/型号。
- 与向量混合（RRF/加权）。

### 6.3 混合检索

```
score = α × vector_score + (1-α) × keyword_score
或 RRF: 1/(k+rank_vector) + 1/(k+rank_keyword)
```

**建议**：先混合，再重排。

---

## 7. 检索链路

```
用户问题
→ 查询改写（同义/缩写/多语言/去歧义）
→ 多路召回（向量/关键词/多查询）
→ 权限过滤（tenant/acl）
→ 去重/近重复
→ 重排（cross-encoder/LLM）
→ Top-K（3–10）
→ 上下文打包（父子块/相邻块）
→ 引用标注
```

### 7.1 查询改写

- 补全缩写/型号（D11、EBOM）。
- 多查询（同义/子问题）。
- 过滤条件抽取（时间/部门/车型）。

### 7.2 权限过滤

- 检索前过滤（tenant/acl）优先，避免泄露。
- 文档级 + 片段级；用户/组/角色。
- 无权限片段不进入上下文，也不出现在引用。

### 7.3 重排

- cross-encoder 精度高、成本中。
- LLM 重排成本高，适合高价值。
- 规则：标题/编号/时间加权。

### 7.4 上下文打包

- 父子块：小块命中，取父块。
- 相邻块：补上下文。
- 去重；按相关度/时间排序。
- 预算：引用 ≤ 上下文 25–30%。

---

## 8. 引用

```json
{
  "doc_id": "d1",
  "chunk_id": "c1",
  "title": "BOM 相关概念定义说明",
  "section": "3.2 采购类型",
  "page": 12,
  "url": "https://...",
  "snippet": "...",
  "score": 0.87
}
```

- 回答中标注 `[1]`；可点击跳转。
- 无引用 → 标注「不确定/未找到依据」。
- 引用要可追溯（版本/时间）。

---

## 9. 新鲜度与增量

| 机制 | 说明 |
|---|---|
| 增量同步 | 游标/时间/哈希 |
| 版本 | 文档版本；旧版本失效 |
| 删除同步 | 源删除→索引删除 |
| TTL | 临时/低可信内容 |
| 重建 | 定期全量/模型升级 |
| 一致性 | 索引与源对账 |

---

## 10. 权限与多租户

- 文档/片段带 tenant_id + acl。
- 检索强制过滤；不能先检索后过滤。
- 引用不泄露无权限内容。
- 跨租户索引隔离（collection/partition/prefix）。
- 审计：谁查了什么、引用了什么。

---

## 11. 评测

| 指标 | 说明 |
|---|---|
| Recall@K | 相关片段是否召回 |
| Precision@K | 召回里有多少相关 |
| MRR/nDCG | 排序质量 |
| 引用准确率 | 引用是否支撑答案 |
| 答案支撑率 | 回答是否有依据 |
| 延迟/成本 | 检索开销 |
| 无答案识别 | 不知道时是否承认 |

**方法**：构造 100–300 问 + 标注相关片段；离线回归 + 线上反馈。

---

## 12. 失败模式

| 失败 | 原因 | 对策 |
|---|---|---|
| 召回不到 | 切分/改写/索引 | 调 chunk/多查询/混合 |
| 召回噪声 | Top-K 太大/重排弱 | 重排/阈值 |
| 引用错 | 片段/页码错 | 元数据校验 |
| 权限泄露 | 先检索后过滤 | 检索前过滤 |
| 过期 | 未增量 | 同步/版本 |
| 上下文爆 | 片段太多 | 压缩/父子块 |
| 幻觉 | 无依据 | 强制引用/拒答 |

---

## 13. 实施顺序

1. 文件/文档接入 + 解析 + 切分。
2. Embedding + 向量库 + 基本检索。
3. 引用 + 上下文注入。
4. 权限过滤 + 多租户。
5. 混合检索 + 重排。
6. 增量/删除同步。
7. 评测集 + 回归。
8. 多源 Connector/代码/表格。

---

## 14. 验收标准

- [ ] 至少 2 类数据源可接入。
- [ ] 解析/切分/元数据完整。
- [ ] 混合检索 + 重排可用。
- [ ] 引用可追溯。
- [ ] 权限/租户过滤在检索前。
- [ ] 增量/删除同步。
- [ ] 有评测集与指标。
- [ ] 无答案能承认。
