# 75 记忆体系与上下文持久化

## 1. 为什么需要记忆

没有记忆的 Agent：

- 每次都要重复背景；
- 记不住用户偏好/约束；
- 长任务断点后无法继续；
- 跨会话无法积累经验。

但记忆也会带来：隐私、过期、冲突、成本、上下文污染。

---

## 2. 记忆分层

| 层 | 内容 | 存储 | 生命周期 |
|---|---|---|---|
| Working Memory | 当前轮的上下文 | 内存/Redis | 一轮 |
| Session Memory | 当前会话摘要/实体 | DB/Redis | 会话 |
| Task Memory | 计划/进度/待办 | DB | 任务 |
| User Profile | 偏好/角色/常用信息 | DB | 长期 |
| Semantic Memory | 事实/知识 | DB/向量 | 长期 |
| Episodic Memory | 历史事件/经历 | DB/向量 | 中期 |

---

## 3. 写入策略

### 3.1 什么值得记

| 类型 | 例子 | 是否记 |
|---|---|---|
| 显式偏好 | 「以后用表格回答」 | 是 |
| 稳定事实 | 「我负责 D11 项目」 | 是（需确认） |
| 临时状态 | 「今天先看 A」 | 会话级 |
| 敏感信息 | 密码/身份证 | 不记 |
| 一次性指令 | 「这次用英文」 | 会话级 |

### 3.2 写入方式

- 显式：用户说「记住…」→ 确认后写。
- 隐式：模型抽取 → 置信度阈值 → 写候选/待确认。
- 任务：计划/进度自动写。
- 禁止：无确认写敏感信息。

### 3.3 去重/冲突

- 同一 key 新值覆盖旧值（带版本/时间）。
- 冲突：保留最新 + 标记；或让用户确认。
- 去重：语义相似合并。

---

## 4. 检索

```
query → 相关性（向量/关键词）
     + 时间衰减（越新越重）
     + 重要性（用户标记/频次）
     + 作用域（user/agent/tenant）
→ Top-K → 注入上下文
```

**预算**：记忆 ≤ 上下文 10–15%；超出摘要。

**规则**
- 只取与当前任务相关的记忆。
- 敏感记忆需权限/脱敏。
- 不把记忆当指令（防注入）。

---

## 5. 摘要与压缩

| 对象 | 策略 |
|---|---|
| 会话 | 每 N 轮摘要；保留最近 K 轮原文 |
| 任务 | 计划/进度/结论 |
| 用户 | 偏好/角色/长期目标 |
| 事件 | 时间/参与人/结果 |

**摘要要求**：保留事实/数字/结论/未完成项；丢弃寒暄；可追溯原文。

---

## 6. 遗忘

| 机制 | 说明 |
|---|---|
| TTL | 临时记忆过期 |
| 重要性衰减 | 长期不用降权 |
| 容量上限 | 每用户/Agent 限制 |
| 用户删除 | 一键删除/导出 |
| 合规删除 | 租户/用户级 |
| 冲突清理 | 旧值失效 |

**原则**：记忆不是永久档案；可解释、可删除。

---

## 7. 隐私与安全

- 明示：告诉用户会记什么。
- 同意：敏感信息需确认。
- 隔离：租户/用户/Agent。
- 加密：存储加密；日志脱敏。
- 删除：用户可删；合规可删。
- 审计：谁写入/读取。
- 防注入：记忆内容标记为数据。

---

## 8. 数据模型

```sql
memory_item(
  id, tenant_id, scope,          -- user/agent/tenant
  owner_id, agent_id,
  memory_type,                   -- profile/fact/episodic/task
  key, value, value_type,
  importance, confidence,
  source_session_id, source_message_id,
  version, status,               -- active/superseded/deleted
  expire_time, create_time, update_time
)

memory_embedding(
  id, memory_id, model, vector, create_time
)
```

**索引**：`(tenant, scope, owner, type, status)`；向量索引。

---

## 9. 失败模式

| 失败 | 后果 | 对策 |
|---|---|---|
| 记错 | 错误偏好 | 确认/置信度 |
| 过期 | 旧信息 | TTL/版本 |
| 冲突 | 矛盾 | 最新/确认 |
| 污染 | 注入 | 标记/过滤 |
| 泄露 | 隐私 | 隔离/权限 |
| 上下文爆 | 贵 | 预算/摘要 |
| 无法删除 | 合规 | 删除链路 |

---

## 10. 评测

| 指标 | 说明 |
|---|---|
| 记忆召回 | 该用的用了 |
| 记忆精度 | 不该用的没用 |
| 冲突率 | 矛盾 |
| 过期率 | 旧值 |
| 用户满意度 | 是否「懂我」 |
| 删除成功率 | 合规 |

---

## 11. 实施顺序

1. 会话摘要/任务记忆（P0）。
2. 用户偏好（显式确认）。
3. 记忆检索/注入。
4. 去重/冲突/过期。
5. 删除/导出/审计。
6. 语义/情景记忆 + 向量。
7. 评测/优化。

---

## 12. 验收标准

- [ ] 会话摘要可用，长对话不爆。
- [ ] 用户偏好可显式记住/删除。
- [ ] 记忆检索相关且不超预算。
- [ ] 冲突/过期有策略。
- [ ] 租户/用户隔离。
- [ ] 可删除/导出/审计。
- [ ] 有评测指标。
