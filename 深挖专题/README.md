> 面向「已经知道要做什么」之后，继续往下钻的 8 个硬骨头。

## 2. 阅读顺序

### 做知识型 Agent

`74 → 75 → 76 → 77`

### 做平台底座

`77 → 78 → 79 → 80`

### 做安全/合规

`80 → 81 → 74（权限）→ 76（工具）`

### 做性能/成本

`77 → 78 → 79 → 75（上下文）`

## 3. 每个专题的产出

- 一张架构图/数据流。
- 关键表/接口/协议。
- 失败模式与降级。
- 实施顺序（P0/P1/P2）。
- 验收标准。
- 与其他文档的交叉引用。

## 5. 使用建议

- 不要一次全做；按主次编排选 1–2 个专题。
- 每个专题先做「最小可用」，再补「失败/安全/成本」。
- 专题产出要回写到实施蓝图（字段/接口/配置）。
- 所有专题都要有评测与观测，否则无法证明有效。
